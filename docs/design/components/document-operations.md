# 文書操作と閲覧状態

[設計全体像に戻る](../index.md)

## 責務と対象範囲

CLI、リンク、ツリー、F5、ファイル監視、履歴移動で共通に使う文書操作を定義します。`app`が文書・検索・履歴の採否を管理し、`infra`は読み込み、`ui`は位置の取得と適用を担当します。

## インターフェースと契約

操作には起点、対象ファイル、必要なら見出しIDまたは履歴先を持たせます。読み込み要求には世代を、CLI起点なら応答先を対応付けます。具体的なRustの型名は固定しません。

| 操作 | 読み込み・表示位置 | 履歴 |
|---|---|---|
| 初回のファイル表示 | 読み込み成功後に先頭を表示 | 最初の項目を作る |
| CLIで別ファイルを開く | 読み込み成功後に先頭を表示 | 元の位置を保存し、移動先を追加 |
| ツリーで別ファイルを開く | 通常ファイルの再検査後、成功時に先頭を表示。ツリーのフォーカスを保持 | 元の位置を保存し、移動先を追加 |
| ツリーで同一文書キーを開く | 同一性の確認だけで本文は読まず、世代・位置・検索・監視を変更しない | 追加しない |
| F5、自動更新、CLIで現在と同じファイルを開く | 読み込み成功時の置換直前のスクロール距離を復元 | 項目を追加しない |
| 同一ファイル内の見出しリンク | 現在の文書の見出しへ移動 | 元の位置を保存し、移動先を追加 |
| 別ファイル内の見出しリンク | 読み込み成功後に見出しへ移動 | 元の位置を保存し、移動先を追加 |
| 戻る／進む | 保存したパスを読み込み、保存した距離を復元 | 成功時だけ現在の履歴位置を変更 |

通常のスクロール、検索一致への移動、再読み込みは履歴項目を増やしません。文書や履歴から離れる直前に現在の距離を保存し、戻ってきたときの復元に使用します。戻った後の新しいリンク・別ファイルへのCLI移動は、成功時に進む側の履歴を破棄します。

読み込み中も既存の本文を表示し続けます。読み込み失敗では本文・距離・履歴上の位置を維持し、通知だけを更新します。古い要求の結果は表示と履歴へ適用しません。CLIへの応答は[外部操作の契約](external-control.md)に従って別途完了させます。

## データと状態

| データ | 管理する層と意味 |
|---|---|
| 文書キー | `infra`で解決したファイルの同一性を`app`で使用する。相対・絶対、`.`・`..`、Windowsのパス表記差だけで別文書としない |
| 文書の世代 | `app`。読み込み結果、表示テキスト、位置適用、Mermaid結果がどの文書内容に対応するかを識別する |
| 待機中の文書操作 | `app`。対象、起点、読み込み要求、成功後の位置方針、履歴変更、CLI応答先を対応付ける |
| 閲覧距離 | `ui`が取得する文書上端からの表示上の距離。ソース行番号やブロック番号ではない |
| 履歴 | `app`。ファイル、保存した距離、現在位置を持ち、アプリ終了時に破棄する |
| 位置適用要求 | `app`から`ui`へ渡す対象世代と、先頭・距離・見出しのいずれかの位置方針 |
| 入力と検索 | モードと検索状態は`app`、入力欄は`ui`。本文の表示状態とは生存期間を分ける |

同じファイルかどうかの判定を、CLI・リンク・監視で個別に実装しません。パス解決を`infra`に集め、実際のファイルシステムの扱いに沿って比較します。外部から与えられた文字列の単純な一致だけでは判定しません。

## 処理の流れ

### 読み込みと採用

1. 操作を受け取り、対象と操作の種類を決める。読み込み開始だけでは現在の文書や履歴を変更しない。
2. バックグラウンドで同一性を確認し、ツリーではルートから対象まで再検査する。同一文書キーのツリー要求だけは未読で完了する。それ以外はUTF-8として読み込む。BOMは既存処理と同様に除く。
3. 完了時に要求が有効かを確認する。古い完了は表示に適用せず、CLI応答があればその読み込み結果を返す。
4. 有効な成功では、置換直前の距離を取得し、操作に応じて文書と履歴を更新する。待機中にユーザーがスクロールした場合も、再読み込みでは置換直前の距離を使う。
5. 本文の世代を更新し、新しい表示テキストで検索を再計算する。Normal・Commandでは確定済み検索語、Searchでは入力中の検索語を使う。
6. `ui`へ本文と位置方針を渡す。読み込み失敗では既存状態を残す。

### 表示位置の適用

- 本文の解析とレイアウトが対象世代に対応してから、先頭・見出し・距離の位置要求を適用する。
- 距離は新しい文書のスクロール可能範囲へ収める。古い文書のブロック番号を新しい文書へそのまま渡さない。
- 解析・レイアウト待ちの間に別の文書へ切り替わった場合、古い世代の位置要求は適用しない。
- Mermaidの後付け表示に合わせて位置を復元し直さない。内容を基準に読んでいた箇所を追跡する処理も追加しない。

距離取得と復元に用いるGPUIの公開APIは、長い段落、表、画像、仮想化された画面外ブロックを含む結合テストで先行確認します。プロトタイプで使う論理ブロック位置を、文書全体の距離と同一視しません。

### 見出しリンク

リンク解決結果にはファイルと見出しIDを別々に保持します。同一文書内のリンクでもIDを捨てず、フラグメントのURLエンコードを解決します。

見出しの抽出と表示位置の対応付けには、TextViewと同じ上流のMarkdown解析結果を使います。装飾を除いた見出しテキストから要件のGitHub互換IDを生成し、文書全体で衝突を避けます。単に同名見出しを数えるだけでなく、番号付きIDと他の見出しから生成したIDの衝突も確認します。

ファイルを開けても見出しがなければ、その文書の先頭を表示して通知します。同一ファイル内の不明な見出しも先頭へ移動します。これはファイル読み込み失敗とは分けます。

### 自動更新との接続

監視対象は要求中のファイルではなく、採用済みの現在のファイルとします。別ファイルの読み込み成功後に監視対象を切り替え、失敗では元の監視を続けます。

監視はエディターの置換保存でも追従できるようにし、重複通知を集約して共通の再読み込み操作へ渡します。古い監視対象からの通知は対象を確認して除外します。別ファイルへの切り替え待ちを、元ファイルの監視通知で取り消さないようにします。

### 入力中の更新

外部CLI操作と自動更新では入力欄のEntityと入力内容を保持します。本文更新のために入力欄を作り直したり、空文字を設定したり、入力を確定・取消したりしません。

検索一致の更新による自動移動は行いませんが、外部CLIのスクロールや履歴復元は実行します。検索取消時は、保存していた一致が現在の文書世代に属するときだけ復元します。

## 検証観点

- [ ] `app`のテストで読み込み成功・失敗・逆順完了、履歴の確定、進む側の破棄を確認する。
- [ ] `core`のテストで相対リンクとフラグメント、日本語・装飾・重複・衝突する見出しIDを確認する。
- [ ] GPUI結合テストで長い段落・表・画像を含む再読み込みと、文書短縮後の距離復元を確認する。
- [ ] 入力中の本文置換でモードと文字列を維持し、古い世代の位置・一致を復元しないことを確認する。
- [ ] 実ファイルの上書き・置換保存、切り替え失敗、古い監視通知を含む結合テストを行う。
