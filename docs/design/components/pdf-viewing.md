# PDF表示の基本設計

[設計全体像に戻る](../index.md)

## 責務と対象範囲

[PDF表示の要件](../../requirements/features/pdf-viewing.md)を既存の共通文書操作へ接続する。Windows・読み取り専用・同じ本文領域という前提を維持し、初期版では表示とスクロール応答性の確認に絞る。ここでは構成・責務とforkのAPI拡張方針を定める。準備・配送・採用・取消・解放の型と状態契約、および実装段階の境界は[PDF接続契約](pdf-viewing-contract.md)を正本とする。

## 構成と責務

| 対象 | 責務と境界 |
|---|---|
| app | 共通文書操作、要求IDと結果採否、文書・履歴・入力モードの管理。PDFエンジンやGPUIの可変状態を持ち込まない |
| infra / runtime | 同一性確認、共通の形式判定に従うI/O、非同期結果の配送。PDFバイト列はアプリのI/O境界で一度だけ読む |
| ui | `DocumentView`のMarkdown／PDFを切り替え、共通の操作メソッドを`match`で振り分ける。キー・モード・入力UIはアプリ側に置く |
| 薄いPDF adapter | fork型をアプリ独自のopaque型で包み、準備・表示の接続、エラー変換、cleanup呼出しを担う。gpui-pdf／hayro型への直接依存をここだけに閉じ込める |
| gpui-pdf fork | hayroによる解析・描画、仮想化、バックグラウンド描画、ズーム、画像・GPU資源の寿命管理を再利用する |

独自のPDFビューアーを一から実装しない。Markdownは既存のTextView系を維持する。汎用trait・プラグイン基盤を先行導入せず、形式別の表示実装をenumで分ける。

既存の[文書操作と閲覧状態](document-operations.md)にあるUTF-8・ソース行・検索再計算・監視・距離復元はMarkdown中心の契約である。PDFのバイト列・解析完了を共通採用処理へ接続し、PDF検索・自動更新・履歴位置復元を初期版へ持ち込まない。一方で文書間の履歴と失敗時の保持は共通の仕組みを維持する。

## 共通入口・形式・データの方向性

- 公開する文書オープン入口は既存の`DocumentOperation::Open(path)`系を維持する。公開APIを`open_markdown`／`open_pdf`へ分裂させない。
- 形式判定は一か所に集める。`DocumentFormat { Markdown, Pdf }`は形式を表し、`.md`と`.markdown`等の拡張子ごとにvariantを作らない。判定規則は[要件](../../requirements/features/pdf-viewing.md#形式とオープン)を正本とし、ツリーの表示・オープン可否と混同しない。
- 内容を持つenumの方向性は`DocumentContent::Markdown { source: Arc<String> }`／`Pdf { bytes: Arc<Vec<u8>> }`とする。`LoadedDocument`はキーとcontentを保持し、contentと食い違い得る形式タグを重複保存しない。
- この型表記は設計の方向性であり、全内部シグネチャを確定するものではない。解析済みPDFとPDF固有のUI状態はPDF側に閉じ込める。

## オープンと結果採用

1. CLI・ツリー・Markdownリンクの要求を共通入口へ流し、既存の要求ID・同一文書判定・非同期採用制御を再利用する。
2. 読み込みが必要なら、Markdownは従来のUTF-8処理、PDFはバイト列としてアプリのI/O境界で読む。forkにバイト列を受け取る初期化入口を追加し、`PdfView`にパスから再読み込みさせない。
3. PDFを解析し、ページ寸法を取得してから成功・失敗を共通の完了／エラー処理へ返す。準備中のPDFと採用済み文書を区別し、I/O成功だけで採用やCLI成功を確定しない。解析中も現在の文書・位置・履歴を保持する。
4. 採用直前に要求が現在も有効か確認し、有効な解析成功だけを共通の文書採用処理へ渡す。遅れて完了した旧要求は採用しない。
5. 共通採用処理で文書・履歴を更新してCLI応答へ接続し、採用したPDFのviewport近傍から描画する。初期幅合わせなどレイアウト依存の適用と、文書の読み込み完了は区別する。全ページのラスタライズ完了をCLI応答条件にしない。

失敗時は既存の文書・位置・履歴を保持し、共通通知方針でエラーを返す。PDF解析失敗後のMarkdownフォールバックは行わない。PDFへの`--line`は未対応として共通操作から明示的に拒否し、ページ移動へ変換しない。

## 所有権・寿命と描画方針

- PDFビューが解析済み文書・描画タスク・ページ画像を所有する。文書の置換・ウィンドウ終了ではGPU画像資源を明示的に解放し、無効な世代の出力を採用しない。準備中の要求が失効した場合も、その要求が所有する資源を後始末する。
- キャンセル可能な処理は中止し、キャンセルできない処理の結果は破棄する。不要になった描画を継続しないよう制御し、後始末はfork側へ集約してappの各経路へ分散させない。これはforkへの要求であり、上流で既にキャンセル可能であるとの保証ではない。
- 上流の仮想化を再利用し、描画の同時実行数と画像キャッシュに上限を設ける。高速スクロールでは古い要求より現在のviewportを優先する。ズーム中は既存ビットマップを保持・拡縮して表示し、新しい解像度の描画結果へ差し替える。
- 上限値・先読み範囲はここでは数値化しない。実装時に上流を調査し、代表的な日本語・画像多数・数百ページのPDFで調整する。測定条件と観測結果を記録し、未確認の性能や保証値を断定しない。

## 検索・履歴・再読み込みの接続

確定済み検索語を、文書固有の一致座標・選択・ハイライトから分離する。PDFへ切り替えても確定語を保持するがMarkdownの結果をPDFへ渡さず、Markdownへ戻る際は対象本文で再計算する。Search中の編集中入力を優先し、確定語で上書きしない。外部CLIでPDFへ切り替えたSearchは入力を保持する。IMEガード後のEnterによるA/Bの終端は[検索仕様](../../requirements/features/search.md#確定取消と検索語の引き継ぎ)に従い、Bを確定せずAを保持し、編集・previewを終了してNormal＋既存INPUT通知へ接続する。PDF上で検索は走らせない。

PDFへの履歴復帰は先頭・幅合わせを指示し、保存位置・倍率を適用しない。同一ファイルのopenをこの復帰処理へ流さない。Markdownの履歴復元は既存どおりとする。初期版のPDFではF5を再読み込みへ配送しないが、将来の再利用に備え、共通loader・解析・置換の構造とMarkdownの再読み込み経路は維持する。

## forkの操作APIと入力分離

forkには次の操作を公開する方向とする。名称・引数・戻り値の完全な一覧はこの基本設計では固定しない。

- 小刻み、半viewport、全viewportの上下スクロールと先頭／末尾への移動。
- 拡大・縮小・幅合わせ。
- 内蔵ショートカット、検索欄、ページ番号入力、ヘッダーを無効にする制御。
- バイト列による初期化と、解析完了・失敗を呼び出し側へ返す接続。

appがキーを共通Action／表示操作メソッドへ変換し、Normal・フォーカス条件で操作を一度だけPDFへ渡す。PDF内蔵ショートカットは無効化する。PDF本文クリックを本文フォーカスへ接続し、Search・Command中の入力は保護する。

可変な`ScrollHandle`を公開せず、`scroll_by`などの操作APIに範囲補正と再描画通知を所有させる。名称は例示であり固定シグネチャではない。小刻み移動はPDFフォントサイズに依存しない固定の論理表示距離、半分／全体は本文viewportを基準とし、先頭・末尾にクランプする。PDFページ境界へのジャンプでviewport移動を代用しない。

ズーム前後の位置アンカーはページindexとページ内の正規化座標で表し、viewport中央付近のPDF上の点を保持する。ページ先頭へ戻さない。幅合わせ中はウィンドウ・ツリーによる幅変更に追従し、手動ズームで解除する。倍率のキー・刻みと40論理pxの小刻み移動は[PDF要件](../../requirements/features/pdf-viewing.md#スクロールとズーム)に従う。ページ間の隙間の詳細アルゴリズムや倍率上限はここでは数値化しない。

将来の検索では内蔵検索欄から独立した検索語設定・次／前の一致移動・強調解除APIを用意し、アプリのSearchモードへ接続する。テキストとPDF矩形の対応を維持し、非連続な一致を矩形群へ戻せるようにする。上流のテキスト収集・検索方式を将来のファジー検索の意味として固定しない。初期版に検索実装やOCRを追加する指示ではない。

## 依存固定と根拠

ghで利用する個人accountへzorite全体をforkし、gpui-pdf crateだけを変更・利用する。実装時に不変のrevisionへ固定する。fork URL・revisionは未作成であり、この文書で仮の値を作らない。crateはMIT、rootアプリはGPL-3.0-or-laterとして区別し、著作権・ライセンス表示を保持する。GPL本体のコードは流用しない。推移依存のライセンス監査は未完了である。アプリとforkで同じ`gpui-pre`を解決するよう依存を揃える。参照時のアプリは`gpui-kit = 0.9.0`、Cargo.lockの`gpui-pre`は`0.3.11`だが、PDFとのビルド・実行互換性を確認した意味ではない。今回Cargoやlockfileは変更しない。

上流0.6.1の参照資料は次のとおり。私有のスクロールハンドルや直接のキー処理があるため、既存公開APIだけに依存せずforkで操作・無効化境界を整える方針とする。

- [gpui-pdf 0.6.1 README](https://docs.rs/crate/gpui-pdf/0.6.1)
- [gpui-pdf 0.6.1 lib.rs](https://docs.rs/crate/gpui-pdf/0.6.1/source/src/lib.rs)
- [gpui-pdf 0.6.1 text.rs](https://docs.rs/crate/gpui-pdf/0.6.1/source/src/text.rs)
- [hayro-interpret Device](https://docs.rs/hayro-interpret/0.7.0/hayro_interpret/trait.Device.html)

上流の文字収集はグリフのUnicodeと境界を利用し、描画順のテキストと対応情報を持つ。検索用の正規化やページ内一致は将来方式の参考であり、縦書き・多段組みの抽出品質やファジー検索のアルゴリズムを保証しない。

## 検証観点

- 形式判定をCLI・ツリー・リンクで重複させず、PDF解析失敗をMarkdownへ流さないこと、バイト列を一度だけ読むことを確認する。
- 読み込み・解析の失敗と逆順完了で既存文書・履歴を壊さず、古い要求のPDF資源が残り続けないことを確認する。
- アプリからの操作と内蔵キー処理が重ならず、PDFクリック後もアプリのキー操作が届き、Search・Command等の入力が保持されることを確認する。
- PDFのF5非対応、履歴復帰の先頭・幅合わせ、Search中の外部切り替えとIME確定後Enter、Markdown復帰時の一致再計算を確認する。
- 置換・終了・要求失効後のGPU解放と旧世代出力の破棄、描画の並列数・キャッシュ制限、スクロール中の優先順位、ズーム中の画像差し替えを確認する。
- 実装時にWindowsでforkとGPUIのビルド・動作互換性を確認する。日本語・画像多数・数百ページの文書による応答性・描画待ち・反復操作時のメモリ確認は[要件の測定観点](../../requirements/features/pdf-viewing.md#受け入れ条件と性能確認)に従う。

これらは検証方針であり、実際のPDF性能や互換性は未検証である。
