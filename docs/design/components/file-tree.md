## 提案する範囲と仕様変更

推奨する最小案は「初期状態は非表示の左サイドバー、表示切り替え、フォルダー展開、現在文書の強調」です。ファイル確定で開く機能は便利ですが、以下の選択を先に決める必要があります。

| 選択 | 利点 | トレードオフ |
|---|---|---|
| 構造の閲覧のみ | CLI入口を維持できる | ファイルを見つけてもツリーから移動できない |
| ツリー内のMarkdownを確定して開く（推奨候補） | リンクのない文書へ移動できる | CLIと文書内リンクに加える第三の入口として、要件の明示的変更が必要 |

後者を採用する場合、全体要件・ファイル表示・画面操作・リンクと履歴・文書操作の仕様を更新する候補とします。`:e`やファイル選択ダイアログ、編集・作成・削除・移動、複数タブまで自動的に範囲を広げません。

## ルート検出の推奨案

`.marksman.toml`は候補として適切です。[Marksman公式のプロジェクト説明](https://github.com/artempyanykh/marksman/blob/main/docs/features.md#workspace-folders-project-roots-and-single-file-mode)はVCSルートや同ファイルをプロジェクトの印として挙げ、実際の検出はエディターによって異なるとしています。[公式README](https://github.com/artempyanykh/marksman#faq)は空ファイルの作成も案内しています（2026-11-09確認）。以下の優先順位は**mmv向けの提案**であり、Marksman共通のアルゴリズムだという主張ではありません。

1. 読み込みに成功して採用された文書の親から、祖先を1段ずつ調べる。cwdや起動時の文書を固定基準にしない。
2. 各階層で`.marksman.toml`という通常ファイル、または`.git`というディレクトリ／通常ファイルがあれば、その階層で探索を止める。`.git`のファイル形態も候補に含める。
3. 同じ階層に両方ある場合は同じルートになる。表示する検出理由は`.marksman.toml`を優先する案とする。
4. どちらもなければ**文書の直接の親ディレクトリ**を使う。ドライブ／共有のルートまで探索しても、そこを無条件にツリールートにはしない。

距離をマーカー種別より優先します。たとえば`repo/.git`と`repo/docs/.marksman.toml`があれば、`docs/a.md`は`docs`を使います。逆に`notes/.marksman.toml`内の`notes/sub/.git`にある文書は`sub`を使います。外側のMarksmanマーカーを必ず優先する方式ではありません。

| 方式 | 利点 | トレードオフ・判断 |
|---|---|---|
| 最も近い`.marksman.toml`または`.git`（推奨） | 明示的な文書集合とGit利用の両方に対応し、入れ子の近い境界を尊重 | 子Gitリポジトリに入ると外側のノート集合から切り替わる |
| 全祖先の`.marksman.toml`を先に探し、なければ`.git` | Markdown集合を強く優先できる | 遠いマーカーが近いリポジトリ境界を越える |
| `.marksman.toml`だけ | 文書集合の意図が明確 | マーカーを置かないGit利用者には親ディレクトリしか見えない |
| 専用マーカー／ユーザーによるルート指定 | mmv独自の意味や例外を表せる | 新規設定と操作の仕様が増えるため、必要性が出るまで保留 |

マーカーは存在だけを見る案とし、TOML設定の読み込み・LSP起動・Gitコマンド実行は行いません。空・不正TOMLでも印として扱い、mmvからマーカーを生成・変更しません。これなら読み取り専用と整合しますが、Marksmanの除外設定などを引き継ぐものではないことを明確にします。

ルートは表示範囲であり、ファイルアクセスの許可境界ではありません。既存のCLI・文書内リンクでルート外に移動できる契約は維持する案です。

### パスと切り替えの論点

- 推奨：現在文書の`DocumentKey`が表す正規化済みパスの親を使う。既存の同一性確認に合わせられるが、symlink経由で開いた場合は見かけの配置と異なる。表示名に元パスを使うかも要決定。
- 推奨：別文書の採用成功時にルートを再評価する。失敗・古い完了では現在のルートや現在文書の強調を変えない。同じルートなら展開状態を保持し、異なるルートなら初期化する。
- ルートを毎回追従させると入れ子で表示範囲が変わる。ルート固定／複数ルートは別案として保留する。
- マーカーの権限エラーを「存在しない」と同一視しない。推奨は探索を打ち切って文書の親を暫定表示し、検出失敗をツリー内に示す。本文表示は継続する。
- ドライブとUNC共有の最上位で終了し、ネットワーク・大量階層でもUIを待たせない。再評価中に別文書へ移った場合は古い結果を捨てる。

## 表示・操作の推奨案と未決定事項

ここからもすべて提案です。キー名や寸法・永続化を確定事項にはしません。

| 論点 | 推奨案 | 判断が必要な点・代案 |
|---|---|---|
| 表示切り替え | 左サイドバー、起動時は非表示、同一セッションでは状態保持 | トグルのキー／クリック入口、起動間の保存、Lua設定への追加可否 |
| レイアウト | 本文はツリーを除く利用可能幅の中で配置・最大幅を適用し、下部2行は全幅を維持 | 幅・リサイズ・最小本文幅・狭いウィンドウの挙動。オーバーレイなら本文幅は安定するが本文を隠す |
| 開閉と閲覧位置 | 開閉だけでは文書を再読み込みせず履歴も追加しない。距離を可能な範囲で保つ | 幅変更による折り返しで同じ段落は保証できない。既存の内容基準復元を対象外とする方針との整合 |
| フォーカス | モードと別に本文／ツリーの入力先を区別。ツリー内の矢印は項目移動・展開、Enterは確定、Escは本文へ戻す候補 | `j/k`等の扱いとトグルキーを決定。`Ctrl+b`は既存の本文ページ移動なので流用しない |
| 入力中 | Search・Command・リンク選択パネルではツリーへのフォーカス移動／ファイル確定を抑止する案 | マウス操作も含めて明文化。外部CLIは従来どおり受け付け、入力・IME・外部アプリのフォーカスを保持 |
| ファイル操作 | 選択移動だけでは開かず、Enterなど明示確定で開く | クリック1回／ダブルクリックのどちらを確定にするか。同じ文書は既存Openと同じ再読み込み候補 |
| 表示対象 | 初期案はディレクトリと`.md`／`.markdown`（拡張子は大文字小文字を区別しない） | 拡張子集合を要決定。既存のCLI／リンク読込に新しい拡張子制約を波及させない |
| 順序・名称 | フォルダー優先、名前順。現在文書と単なる選択行を区別 | 日本語・大小文字・同名時の安定した順序と長いパスの表示 |
| 除外 | `.git`内部は常に列挙しない。その他のフォルダーは遅延展開する | dotfile、Windows Hidden属性、`node_modules`等の扱い。`.gitignore`準拠は利便性と複雑さを比較し、初期案では読み込まない |
| 空フォルダー | 全体再帰探索を避け、展開した範囲でMarkdownがなくてもフォルダーは残す | Markdownを含む枝だけに絞ると先行走査の負荷が増える |
| symlink／junction | 初期案はリンク先を自動再帰しない。項目を非展開として明示 | Windows reparse pointの判定とファイルリンクの確定可否を決め、循環・ルート外脱出を検証 |
| 更新 | 初回表示・フォルダー展開・ツリー専用更新操作で非同期再列挙。非表示中は新たな列挙をしない | 自動監視は後続候補。F5は既存の本文再読み込みを維持し、ツリー更新に勝手に転用しない |
| 再評価 | 文書切り替えとツリー専用更新でマーカーも再確認する案 | 同じ文書の自動更新では毎回祖先探索しない。マーカー変更の即時反映を保証するか |

削除・改名・アクセス拒否は、該当行のエラーと再試行で扱います。確定後にファイルが消えた場合は共通読み込みの失敗として元の本文・履歴を保持します。現在文書がフィルター外／削除済みで一覧に出ない場合も、別項目を現在文書として強調しません。

## 採用する場合の実装境界

- `infra`：祖先マーカーの検出、直下の一覧取得、パスと種類の確認。I/Oはバックグラウンドで行う。現在文書の`FileWatch`を、プロジェクト全体の再帰監視へそのまま拡張しない。
- `app`：ルート、検出理由、列挙要求と採否、展開・選択の論理状態を管理する候補。ツリーの要求IDは文書の読み込みIDとは分け、ルート世代＋ディレクトリ＋要求番号で逆順完了・A→B→Aを区別する。
- `ui`：ツリー描画、可視状態・幅、フォーカス、入力受付と本文レイアウト。マウス／キーのツリー操作で本文のNormal操作が同時発火しないようにする。
- ファイル確定は`Viewer::request_operation`から`DocumentOperation::Open`相当へ渡す候補。ツリー起点の識別方法は別途決定する。CLI起点と偽装したり、UIから本文・履歴を直接置換したりしない。
- 別文書の読み込み成功時だけ履歴を確定し、戻った後の新規移動は進む側を破棄。同一文書の再読み込み、検索語保持、監視切り替え、Mermaidの古い結果除外は共通経路に委ねる。
- 共通選択パネルは一時的な絞り込みUI。常設可能な階層ツリーとは生存期間・入力が異なるため、同じコンポーネントにする前提を置かない。GPUIのツリーAPIの採用可否は実装前に別途調査する。

列挙はフォルダーを開いた分だけ行い、巨大な単一ディレクトリにも件数・時間・表示の上限を設ける案とします。上限到達を空フォルダーと区別して表示し、続きの取得／再試行を設計します。具体的な上限と仮想化の要否は計測後に決めます。非表示化やルート変更時は不要な要求を失効させ、キャンセルできないI/Oの完了も採用しません。

5. 合意した項目だけを要求・要件へ移し、既存の未実装仕様との順序を決めてから実装に着手する。
