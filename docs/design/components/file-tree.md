# ファイルツリーとpaneの詳細設計

[設計全体像に戻る](../index.md)

## 責務と対象範囲

根拠は[ファイルツリー](../../requirements/features/file-tree.md)、[画面と操作モード](../../requirements/features/viewer-ui.md)、[表示・配色設定](../../requirements/features/display-settings.md)、[ファイル表示と更新](../../requirements/features/file-viewing.md)です。

左ツリー・右本文の固定2領域を扱います。paneを表示領域とフォーカスの共通枠とし、中身を分離する大枠に沿います。任意分割、複数本文、汎用paneプラグイン、ツリーからのファイルオープンは対象外です。以下の配置・型・フォーカス管理・要求管理は設計案であり、利用者向けの確定仕様と区別します。

## 構成と責務の案

具体的な配置と型名は仮案です。`Viewer`が組み立て、pane同士は直接操作しません。

| 配置案 | 責務と境界 |
|---|---|
| `src/ui/pane.rs` | 共通枠、固定配置、可視状態、幅制限、pane移動。文書読み込み・履歴・監視は扱わない |
| `src/ui/file_tree.rs` | 行描画、論理カーソルの表示、ツリースクロール。論理状態の正本はapp |
| `src/ui/input.rs` | pane別のキー受付、入力モード・パネル・IMEによる抑止 |
| `src/app/file_tree.rs` | ルート、項目、展開、論理カーソル、要求発行と結果採否 |
| `src/infra/file_tree.rs` | 祖先マーカー探索、直下一覧、項目種別の判別 |
| `src/runtime/file_tree.rs` | バックグラウンド取得と完了配送。結果採否は判断しない |

`PaneLayout`／`Pane`は仮称です。`Pane<T>`や共通traitを先行して一般化しません。`ui`は可視状態・スクロール、`app`は論理状態を所有する案とし、カーソルの正本を二重管理しません。層の共通境界は[モジュール構成](module-boundaries.md)に従います。

## pane配置・フォーカスの案

- ツリー幅240論理px、本文pane最小幅240論理pxを確保します。ウィンドウ最小幅は両者に境界線などの必要幅を加えて設定し、共通枠のレイアウトと整合させます。ドラッグリサイズ・幅保存は追加しません。本文paneの最小幅と`view.max_width`による内容幅の上限は区別します。
- 本文の最大幅・中央／左配置は本文paneの内部で計算し、状態行・入力行はpane外の全幅に置く案です。
- paneごとにGPUIの`FocusHandle`を持ち、実フォーカスを正本とする案です。別の論理フォーカス値を正本として重複させません。
- 初期フォーカスは要件どおり本文です。表示するだけではフォーカスを移さず、隠すツリーにフォーカスがあれば本文へ戻す案です。CLI操作・再描画では奪いません。
- ツリー非表示でもツリー状態と`DocumentView`を破棄しない案です。表示切替だけで本文・履歴・入力欄を作り直しません。
- 本文幅変更時は変更前の上端からのスクロール距離を保持し、レイアウト後に有効範囲へ補正する案です。折り返し後の同じ段落の維持は保証しません。

描画は要件の行全体背景、アクティブ時の左端細線、非アクティブ時の控えめな背景、文字を薄くしない規則、`▸`／`▾`に従います。現在本文のファイル強調・自動展開・自動スクロールは行いません。標準配色を使い、ツリー専用Lua配色APIを作りません。カーソル行が見える最小限だけスクロールします。

## 入力契約

キー対応は[要件の入力表](../../requirements/features/file-tree.md#入力とpane移動)を正本とします。`j/k/h/l`と矢印、Enter、`g g`／Home、`G`／End、`r`をツリー側へ振り分け、本文の同じキーへ伝播させない設計案です。

`Ctrl+W`→`h/l`と`Ctrl+Shift+e`はpane共通の操作として受付をまとめる案です。移動先なしでは何もせず、非表示のツリーを移動操作だけで開きません。Search・Command・リンク選択パネル・IME変換中は受付を抑止します。ツリーでは本文検索・履歴移動・本文再読み込み・F5を受け付けません。行クリックによる選択・展開は実装対象にしません。

`src/ui/input.rs`では本文操作と`g g`を`KeyBinding::new()`で登録しています。ツリー操作も同じ機構を使い、pane移動は`ctrl-w h`／`ctrl-w l`として登録します。取消・待機時間・無効キー・修飾キーはGPUI標準動作に任せ、独自の連続入力処理やCtrlを保持した2打目の別名登録は追加しません。

登録だけではpane別の受付は完成しないため、入力コンテキストと受付条件を分離します。既存のEscと空CommandでのBackspaceはキーイベントで直接処理されているため、その干渉と、モード・IME・フォーカス・可視状態変化後の入力漏れを実装時に確認します。GPUIの待機・イベント消費・再処理の実動作は未検証です。

## データと状態の案

| 状態 | 意味・生存期間 |
|---|---|
| ルートとルート世代 | 現在の表示範囲と、その範囲への要求の有効性 |
| 項目IDと親子関係 | ルート＋列挙相対パスをIDにする案。行番号やリンク先の正規化パスを正本にしない |
| 展開状態・直下一覧 | 展開した通常フォルダーの状態。閉じた内部を先行取得しない |
| 論理カーソル | 項目IDで保持。ファイルとフォルダーに同じ削除時規則を適用 |
| ルート探索要求番号 | 新しく採用された文書に対応する探索だけを有効にする |
| フォルダー別取得番号 | 重複・逆順完了を整理し、不要な結果の採用を防ぐ |
| 可視状態・スクロール | uiで保持。同一ルートの再表示・文書移動で復元 |

項目ID案では改名は削除＋追加として扱います。親が削除されたら配下項目の展開・カーソル関連状態と要求を無効化する案です。取得失敗を削除と解釈して配下を消してはいけません。

## ルートと取得の流れ

### 文書採用からの追従

1. 文書読み込みに成功して採用されたときだけ、その正規化済みパスからルート確認を要求します。文書読み込み失敗・古い文書完了ではツリーを変更しません。
2. 正規化済み文書パスの親から、`tree.root_markers`のいずれかがある最寄りの祖先を探し、なければ文書の親を使います。既定値は`.marksman.toml`と`.git`です。空配列なら探索せず文書の親を使います。
3. 探索中は旧ツリーの操作を止め、取得中の文言は出しません。探索要求番号で古い完了を棄却する案です。
4. 同一ルートなら展開・カーソル・スクロールを保持して再開し、一覧は再取得しません。別ルートならルート世代を変えて旧要求を無効化する案とし、状態を初期化してルート行カーソル・直下だけの展開にします。
5. 非表示中に文書が変わればルート確認を再表示まで遅延します。再表示だけでは一覧を再取得しませんが、別ルートなら新ルートの初回取得を行います。

ドライブ／UNC共有の最上位で探索を終了する案です。symlink経由で文書を開いても、基準は正規化済み文書パスです。マーカー探索がアクセス拒否になった場合は文書の親を暫定ルートとし、探索失敗や暫定ルートの通知を画面には出しません。「マーカーなし」という探索結果とは区別します。親の一覧も取得できなければ、ルート利用不能時の契約を適用します。

### 展開と明示更新

- 初期状態はルート行を表示し直下だけ取得します。以後は通常フォルダーの展開と`r`だけを更新契機にし、自動監視は追加しません。
- `r`ではルート直下と展開中フォルダー直下を再取得し、閉じた内部、マーカー再探索、本文再読み込みは対象にしません。再展開時は再取得します。
- 各直下を一括取得し、全体を要件のフォルダー優先・大小文字非区別の名前順・元名による同順位固定で整列します。部分取得・続きを取得する状態は作りません。
- 初回取得中は子を表示せず、再取得中は既存一覧を残します。いずれも取得中表示は不要です。
- 同じフォルダーの重複取得はまとめます。I/OはUIスレッド外で実行し、同時実行数を制限する案です。上限数はここでは決めません。
- 結果はルート世代・フォルダー別取得番号・展開状態・親の生存で採否を判定する案です。文書読み込みの要求管理とは分離し、A→B→A、逆順完了、親削除、折り畳み後の不要結果を棄却します。棄却とは完了結果を状態へ反映しないことであり、I/Oの中断成功は前提にしません。
- 可視状態だけでは要求を無効化しません。非表示中も同じルートに対する有効な結果を状態へ保存し、再表示時は保存済み一覧を使います。初回取得がまだ進行中なら同じ要求の完了を待ち、再取得を開始しません。非表示中に文書が変わった場合も、再表示時のルート確認で別ルートと判明すれば旧状態を破棄し、旧要求を無効化します。

### 再取得後のカーソル

項目が残ればIDで維持します。削除なら更新前の兄弟順を保持して、(1)後ろの残存兄弟の最初、(2)前の最も近い残存兄弟、(3)親、(4)存在する最も近い祖先の順で選びます。同じ行番号の別項目へ移す旧方式は使いません。削除された親の配下にカーソルがある場合も、存在する項目へ補正し、無効な配下状態・要求が復活しないようにする案です。

## 異常時と境界条件

- フォルダー取得失敗は空・削除と区別します。既存一覧とカーソルを保持して更新失敗をツリー側に表示し、`r`または閉じた後の再展開で再試行します。本文・入力行は置き換えません。
- ルート利用不能時はルート行を残してカーソルを置き、文言は「アクセスできません。」だけとします。再試行案内は付けません。ルート名・パス・フォーカスを保持し、`r`とpane移動は有効です。カーソル解除案は採りません。
- 全ファイル・隠しファイルを表示し、`.gitignore`を参照しません。`.git`は表示だけとし、通常フォルダーのみを展開します。symlink・junctionは手動を含め展開せず、クラウド固有の特殊フォルダー対応は追加しません。
- その他のreparse pointも表示のみとします。reparse pointをすべてsymlinkと呼ぶのではなく、展開対象外という共通の扱いにします。判別失敗は通常フォルダーとみなさず、取得失敗として扱います。

## Windowsの項目判別

一覧は`std::fs::read_dir()`で列挙し、リンク先をたどらない`DirEntry::metadata()`とWindowsの`MetadataExt::file_attributes()`で項目自身の属性を調べます。ディレクトリであり、`FILE_ATTRIBUTE_REPARSE_POINT`がなく、名前が`.git`でない項目だけを展開対象にします。

属性定数は既存の`windows-sys = 0.61.2`と有効化済みの`Win32_Storage_FileSystem`を使います。追加クレートやWindows APIによる独自の列挙処理は不要です。Windowsの`DirEntry::metadata()`は追加システムコールなしで属性を得られます。

`FileType::is_symlink()`は確認したRust 1.97.1のWindows実装ではjunctionも検出しますが、すべてのreparse pointは検出しません。このため、展開可否はreparse point属性で判断します。symlinkとjunctionの厳密な種類分けは今回必要なく、`junction`クレートは追加しません。

展開直前には`std::fs::symlink_metadata()`で項目自身を再確認します。ただし確認直後の置換競合を完全に防ぐ保証ではありません。クラウド固有の特殊フォルダーも属性によっては展開対象外になります。実機での分類・動作は未検証です。

参照: [DirEntry](https://doc.rust-lang.org/std/fs/struct.DirEntry.html)、[Windows MetadataExt](https://doc.rust-lang.org/std/os/windows/fs/trait.MetadataExt.html)、[Rust 1.97.1のWindows実装](https://github.com/rust-lang/rust/blob/1.97.1/library/std/src/sys/fs/windows.rs)。

## Lua APIとの整合

`tree.visible`と`tree.root_markers`の契約は[表示・配色設定](../../requirements/features/display-settings.md#ルート判定マーカー)を正本とします。起動時に検証済みのマーカー配列をルート探索へ渡し、一覧更新の`r`や文書再読み込みでは設定を再読み込みしません。

名前・要素型・連続配列の検証は既存の未知キー・不正型拒否と同じ設定境界で行い、不正値では設定全体を標準値へ戻して通知・ログを残します。API仕様の確定を、現在の実装が`tree`を受理済みであることとは混同しません。

## 設計判断

状態をapp、I/Oをinfra、配送をruntime、描画・フォーカスをuiへ分ける案は、ツリー取得を文書読み込み・履歴から独立させるためです。共通枠は固定2領域に必要な範囲に限定します。仮想化描画は提案にとどめ、必須にしません。大量項目向けの部分取得・件数上限・続きの取得という旧案は追加しません。
