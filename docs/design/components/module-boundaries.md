# モジュール構成と責務境界

[設計全体像に戻る](../index.md)

## 対象と前提

1つのcrateと`core`・`app`・`infra`・`ui`の層構造を維持し、責務と状態のまとまりに応じて内部を分割します。行数だけを基準にした分割、関数ごとのファイル化、先行したworkspace化は行いません。

根拠となる製品の範囲は[要求・要件](../../requirements/index.md)、文書・検索・履歴をまたぐ契約は[文書操作と閲覧状態](document-operations.md)、CLIとプロセスの契約は[外部操作の設計](external-control.md)を参照してください。

以下の配置は実装に向けた構成です。既存のファイルは流用し、新しいファイルは対応する責務を移すとき、または機能を追加するときに作成します。予定ファイルの空のひな形を一括生成しません。

## 起動とCLI

| 配置 | 責務 |
|---|---|
| `src/main.rs` | 起動入口、CLIとGUIの役割選択、各層の初期化と接続 |
| `src/cli.rs` | 引数解析、公開CLI操作への変換、ヘルプ・使い方エラー・終了コードへの変換 |

引数解析とコマンド解釈をGPUI初期化から切り離し、GUIを開かずに単体テストできるようにします。ファイル読み込みの採否や履歴更新の判断をCLI側へ重複実装しません。`cli.rs`の抽出は文書・検索状態の分割を始めるための前提条件にはせず、CLIの実装段階で行えます。

## app

| 配置 | 所有する状態と責務 |
|---|---|
| `src/app.rs` | 状態全体の統括。文書切り替えと検索・履歴の更新など、複数の状態をまたぐ遷移を組み合わせる |
| `src/app/document.rs` | 読み込み要求、文書の世代、現在の文書、読み込み結果の採否 |
| `src/app/search.rs` | 確定済み・編集中の検索語、一致範囲、選択中の一致、検索の確定・取消 |
| `src/app/history.rs` | 履歴項目、履歴上の現在位置、戻る／進む、進む側の破棄 |
| `src/app/mermaid.rs` | 図の検出後の生成状態、生成待ちと実行中の管理、古い完了の除外 |

入力モードは全体の操作受付に関わるため、`app`の統括側で扱います。検索取消に必要な検索の復元情報は検索状態と対応付けます。具体的な型名やモード型の配置は固定しませんが、モードの正本を複数の状態へ重複保持しません。

子モジュールは自分の状態について判定・更新し、互いの内部状態を直接変更しません。たとえば文書の読み込み成功を契機に履歴を確定し、検索対象を更新する手順は、統括側の操作としてまとめます。履歴の遷移は`app/history.rs`へ集め、同じ規則を`core`にも重複配置しません。

GPUIのEntity、実ファイル、Pipe、外部プロセスを`app`へ持ち込みません。テストは操作と完了通知を入力し、採用された文書、検索結果、履歴、出力された要求を確認します。

## ui

| 配置 | 責務 |
|---|---|
| `src/ui.rs` | `Viewer`の構築、各UI部分の組み立て、`app`とUIの接続 |
| `src/ui/input.rs` | キーバインド、モード別入力、IME、確定・取消の処理 |
| `src/ui/document.rs` | 本文表示、スクロール、距離の取得・復元、見出しへの移動 |
| `src/ui/status.rs` | 下部2行、モード欄、ファイル名、通知の描画 |
| `src/ui/search.rs` | 表示ブロックと検索範囲の対応付け、強調と一致への移動。既存モジュールを拡張する |
| `src/ui/mermaid.rs` | Markdown拡張と図の表示。既存モジュールを流用する |

キーボードのNormal専用制約は`input`で判定します。`document`の共通移動処理自体はNormal限定にしないため、外部CLIからも同じ移動を使えます。

本文・表示テキスト・位置の情報と、入力欄の生存期間を分けます。本文更新のために入力欄を初期化せず、Commandの入力文字列やIMEの未確定状態を`app`側へ複製しません。

`impl Viewer`を複数のファイルへ移すこと自体を分割の目的にしません。状態と描画・入力のまとまりを明確にし、他の部分がどの情報を受け渡すかを限定します。ただし、接続処理を隠すためだけの汎用コンポーネントやtraitは追加しません。

## infra

| 配置 | 責務 |
|---|---|
| `src/infra.rs` | I/O実装の入口と必要な公開項目の集約 |
| `src/infra/document.rs` | ファイル読み込み、ファイルの同一性確認 |
| `src/infra/watch.rs` | ファイル監視と通知の集約・配送 |
| `src/infra/ipc.rs` | Named Pipeの接続・メッセージ送受信 |
| `src/infra/instance.rs` | 単一起動の所有権、起動調停、GUIプロセスの起動 |
| `src/infra/logging.rs` | エラーログの保存・ローテーション・標準エラーへの代替出力 |
| `src/infra/mermaid.rs`、`src/infra/mermaid/` | 図生成と子プロセス管理。既存実装を流用する |

I/Oごとの資源とライフサイクルをそれぞれに閉じ込めます。文書や履歴へ結果を適用してよいかは、`infra`ではなく`app`が判断します。永続キャッシュ用のモジュールは初期版では追加しません。

## core

現行の検索とリンク・画像のパス解決は小さいため、`src/core.rs`を直ちに細分化しません。見出しID生成など独立した計算が増えた段階で、まとまりに応じてサブモジュールへ分けます。

上流のMarkdown解析結果から取得する見出しテキストと位置の対応付けはUI側、取得済みのテキストからIDを作る純粋な計算は`core`側とします。独自のMarkdown解析器は追加しません。

## 分割の順序と検証

1. [テスト設計](../testing.md)の分割前ケースを既存APIで追加し、基準となる振る舞いを確認する。
2. `app`の文書・検索状態を分け、統括側の連携を維持する。既存Mermaid状態の抽出は、この整理に合わせて行う。
3. `ui`の入力と本文操作を分け、描画構成を整理する。状態表示はまとまりとして抽出する。
4. 履歴・監視・IPC・ログは、機能実装に合わせてそれぞれのモジュールへ追加する。

分割と製品向けの振る舞い変更は、別の変更単位として検証します。テストが示す既存の仕様違反を、ファイル移動のついでに修正したり、期待値を実装へ合わせたりしません。

分割後は単体テストに加え、既存のGPUI結合テストで入力、検索、リンク、Mermaidの接続を確認します。検証の具体的な範囲とコマンドは[テスト設計](../testing.md)に集約します。
