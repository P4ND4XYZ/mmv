## 対応する要件・機能仕様

## 責務と技術選定

[リンク選択](../../requirements/features/links-history.md#キーボードによるリンク選択)には、リンク以外にも再利用できる共通の選択パネルを用います。

- ファジーマッチにはRustの`nucleo-matcher`を採用します。
- パネルは`gpui-kit`経由の`gpui-component`を利用し、公開APIを薄く包む方針とします。入力・候補表示・選択・確定・取消・フォーカス制御を共通化し、リンクの抽出やリンクを開く処理は呼び出し側に残します。
- 照合処理は表示UIから分離し、候補の絞り込み・順位付けと一致箇所をパネルへ渡せるようにします。確定結果は安定した候補IDへ対応付け、表示順の変更で別の候補を開かないようにします。

## 現行実装と変更方針

現行の`src/ui/selection_panel.rs`は独自の重ね表示と`Command` / `CommandState`、独立した`InputState`を使っています。以前検討した`Dialog`の開閉・フォーカス復帰APIは現行の開閉経路では使っていません。入力は`Command`のheaderにあり、プレビューは未実装です。以下は更新後の設計であり、実装済みという意味ではありません。

- 重ね表示、背景クリックの遮断、IME保護、取消と確定の経路を維持する。入力を一覧headerからパネル下部の独立した領域へ移す。
- 共通枠・選択UI・ソース表示・リンク選択制御を以下の責務に分ける。選択変更を安定した候補IDで通知し、初期選択・検索変更・キー操作・マウス操作の全経路を揃える。
- `ui/links.rs`側で候補IDとリンク元のソース位置・宛先を対応付け、選択通知からプレビュー指示へ接続する。プレビューの表示・スクロール状態は`SourcePreview`が持ち、共通パネルにリンクの解釈やファイルI/Oを持ち込まない。
- 既存の`filterable(false)`、`searchable(false)`、独自入力イベント、候補行の一致強調、並べ替え後のIDによる確定を維持する。標準CommandのEscやEnterに製品の取消・IME規則を委ねない。

## 構成と責務の分離

以下のファイル名・型名は変更後の設計案であり、新規部品の実装済みを示さない。現行では枠・入力・IME処理が`selection_panel.rs`に同居し、通知は`Query(String)` / `Confirm(usize)` / `Cancel`である。`links.rs`の`begin_link_selection`が生成・購読・検索・確定を接続し、パネル同一性と解析世代の検証を行っている。

| 配置・型の案 | 責務 | 持ち込まないもの |
|---|---|---|
| `src/ui/floating_panel.rs` / `FloatingPanel` | 注入設定によるサイズ計算・中央配置、枠・背景・重なり、背後クリック遮断、外クリックによる取消要求通知、注入コンテンツの配置 | リンク・候補・検索・Markdownの知識、文書・選択・スクロール状態。80%はリンク選択側から渡し、共通枠の固定値にしない |
| `src/ui/selection_panel.rs` / `SelectionPanel` | 上段左右と下部入力の配置、入力・候補選択、確定・取消・IME保護、選択変更通知、外部から注入するプレビューの配置 | リンク解釈・ファイルI/O。具体的な`SourcePreview`型への直接依存 |
| `src/ui/links.rs` / リンク選択制御 | 部品の組立、通知と指示の接続、抽出・検索・候補と範囲の対応、確定、文書更新による終了の統括 | プレビューの折り返し・描画キャッシュ・スクロール位置の管理 |
| `src/ui/source_preview.rs` / `SourcePreview` | ソースと対象範囲を受け、折り返し・背景強調・独立スクロール・描画キャッシュを管理。ソース位置から描画位置への変換と全文表示の性能対策 | リンク解釈・ファイル読み込み・本文のスクロール操作 |

描画上の親子は`Viewer → FloatingPanel → SelectionPanel → 上段（候補一覧・注入SourcePreview）／下段（検索入力）`とする。既存のツリー・本文・状態行は背後に残す。GPUIのView／Element合成と型付きイベント／コールバックで接続し、兄弟部品を直接呼び合わせず、リンク選択制御が仲介する。生キーを共通枠にすべて集約しない。汎用プラグイン登録、任意分割、大量のtraitは先行追加しない。

## データの所有と寿命

| 状態 | 正本・所有者と寿命 |
|---|---|
| 文書ソース・文書世代 | 既存の文書管理が正本。プレビューへ読み取り専用の共有参照を渡し、全文の別コピーを作らない |
| 全候補とソース範囲 | 文書単位の解析結果。候補ID・表示名・宛先・本文順・範囲を文書世代に対応させる。パネルを閉じただけでは破棄せず、同世代では再利用可能 |
| 検索文字列 | `SelectionPanel`の入力欄が正本。matcherはリンク選択制御が保持する |
| 表示候補・表示順・選択ID | `SelectionPanel`が唯一の管理者。親に別の選択正本を作らない |
| プレビュー対象範囲 | `SourcePreview`の表示状態。選択や確定先の正本にはしない |
| スクロール・折り返し・描画キャッシュ | `SourcePreview`が本文とは独立して管理。元の改行位置は文書単位で再利用し、折り返し後の行・高さは幅・フォント依存のプレビュー情報とする |
| 開閉・購読・対象世代 | リンク選択制御。終了時にパネル固有の入力・選択・プレビュー状態と購読を破棄する |
| サイズ・見た目 | `FloatingPanel`への設定。共通枠には文書・検索・選択・スクロール状態を持たせない |

世代には既存の`Generation`を使う。ファイル名や更新日時ではなく、採用した文書内容の更新時点を識別し、古い候補・範囲を新しい内容へ誤適用しない。

## 通知と指示の契約

以下の通知／API名は仮称であり、既存APIではない。子から親へは型付きイベント／コールバック、親から子へは状態設定・表示指示として接続する。

| 子 → 親 | 発行条件・意味 |
|---|---|
| `FloatingPanel: DismissRequested` | 外クリックによる取消要求。背後への同一クリックは遮断する |
| `SelectionPanel: QueryChanged(query)` | 入力変更。親は絞り込み・順位付けして`SetItems`を返す |
| `SelectionPanel: SelectionChanged(Option<CandidateId>)` | 選択IDの変更。初期選択は親が購読可能になってから通知する。検索更新では新一覧の先頭を選び、同IDなら通知しない。再描画のみでも通知せず、候補消滅では`None`を通知する |
| `SelectionPanel: Confirmed(CandidateId)` | 候補の確定。候補なし・IME変換確定のEnterでは発行しない。入力文字列と一覧が対応しない間も発行しない |
| `SelectionPanel: CancelRequested` | 取消要求。IME変換中のEscは変換取消を優先し、`CancelRequested`を発行しない |
| `SelectionPanel: PreviewScrollRequested(direction)` | IME操作を優先した半画面移動の要求。親がプレビューへ転送する |

ホイールとスクロール位置の管理は`SourcePreview`内で完結させ、親への位置通知を要求しない。プレビュー操作は本文へ伝播させず、検索入力欄のフォーカスを維持する。

| 親 → 子 | 指示の意味 |
|---|---|
| `SelectionPanel: SetItems(query, items)` | その検索文字列に対応する一覧を設定し、先頭または`None`を選ぶ。入力欄とは別の検索正本にはしない |
| `SourcePreview: ShowSource(source, generation)` | 読み取り専用の共有ソースと対象世代を設定する |
| `SourcePreview: RevealRange(range)` | 範囲を強調し、リンク記述位置を縦中央へ移す。文書端では余白を足さず有効範囲へ補正する |
| `SourcePreview: ClearTarget` | 表示・強調・閲覧位置を消去する。共有ソース参照まで破棄する必要はない |
| `SourcePreview: ShowUnavailable` | 前候補のプレビューを消去して位置不明の案内を表示する |
| `SourcePreview: ScrollHalfPage(direction)` | 閲覧位置だけを半画面移動し、強調対象を変えない |

親は検索通知から絞り込みと`SetItems`へ、選択通知から範囲解決とプレビュー指示へ接続する。確定通知では候補IDと世代を検証してから閉じ、既存のリンク移動へ渡す。文書置換による終了は利用者の取消通知とは別経路とする。

すべてのイベントへ世代を付けるのではなく、親が現在開いているパネルの同一性と対象世代を検証する。閉じたパネルからの通知は無視し、世代が一致しない候補ID・範囲は適用しない。検索文字列と表示候補の対応が揃うまで確定を禁止する既存の保護も維持する。

## リンク元のソース位置とプレビュー

プレビュー元は現在の`Document.source`とする。別ファイルの読み込み、リンク先見出しの探索、Web取得、文書オープン要求は使わない。本文用`DocumentView`の表示・スクロール状態を流用せず、ソース全文をスクロールできるプレーンテキスト表示を独立させる。履歴・監視・検索・ツリールート・文書世代を変更しない。

現行の`LinkCandidate`は候補ID・表示名・宛先・本文順を持つが、ソース範囲は持たない。`ui/links.rs`の抽出段階で表示名・宛先・元ソースのバイト範囲を取得し、解析ライブラリーへの依存を抽出側に閉じ込める。候補整理側で宛先解決・重複排除・ID付与を行い、最初の範囲を保持する。Markdownリンクと参照形式リンクはASTの位置情報を利用し、参照形式では宛先の定義行ではなく本文中の使用箇所の範囲を保持する。Markdown記法の画像混在リンクは表示名全体を持つ1候補として、公開APIが保持する範囲と変換後テキストの対応を検証する。HTMLリンクは抽出時に候補から除外し、HTMLアンカーの断片候補やプレビュー用の範囲対応は作らない。本文上のHTMLリンクのクリック処理は変更しない。表示名の文字列検索で位置を推測しない。

候補の同一性と出現位置は別に扱う。現行の同名・同じ宛先をまとめる重複排除を維持し、文書順で最初の出現に対応するソース範囲を候補へ保持する。後続の重複でその範囲を上書きしない。検索・並べ替え後も候補IDを通して同じ範囲を参照し、確定先との対応を維持する。出現切り替え用の状態は追加しない。

ソース範囲は文書世代と組にして保持する。現在の世代・候補との一致と範囲の有効性を確認して表示位置・強調へ適用し、文書置換時は既存規則でパネルを閉じる。選択のたびに全文解析・全文コピーを繰り返さず、文書単位で解析結果や改行位置を再利用する。解析を非同期化する場合のみ、パネルの寿命と選択要求も照合し、古い結果を破棄する。専用のファイル読み込みタスクは不要。

## 表示量とレイアウト

表示中の文書が保持するソース全文をプレビューに使い、本文自体の読み込み方式・上限は本件で変更しない。プレビューでは内容を省略せず、全文閲覧を妨げる上限を設けない。長い行は元ソースを変更せず表示上のみ折り返す。仮想化・分割描画などの描画方式は固定しないが、どの方式でもスクロールで全文へ到達できることを維持する。

初期選択・候補変更時は、リンク元のソース位置に対応するレイアウト位置をプレビューの縦中央へ合わせ、スクロール可能範囲で補正する。文書先頭・末尾では中央からずれてよく、中央化のための余白は追加しない。選択リンクのソース範囲を控えめな背景色で強調し、行番号は表示しない。Markdown全体の構文色分けは追加しない。極端に長い1行、複数行リンク、日本語のUTF-8境界、CRLF、文書先頭・末尾で位置・強調と描画負荷を検証する。

別OSウィンドウは作らず、アプリ内表示領域の幅・高さそれぞれ80%の重ね表示を中央に配置する。モニター寸法は使わない。上段を左の一覧と右のプレビュー、下段をパネル全幅の入力欄とし、小さいウィンドウでも左右を常時表示する。左右の幅比率は固定しない。

プレビューのスクロール状態は本文と分離し、同じ候補の再描画や検索変更だけでは位置を初期化しない。検索欄にフォーカスを保ったまま、`Ctrl+u` / `Ctrl+d`でプレビュー表示領域の半画面上／下へ移動する。プレビュー上のホイールもプレビューだけに作用させ、これらの操作を本文へ伝播させない。既存のIME変換操作の優先、確定・取消の保護を維持する。

候補なしでは`ClearTarget`で表示・強調・閲覧位置を消去し、既存の`No matching links`を一覧に表示する。検索入力と共有ソースは保持する。本文置換で既存規則どおりパネルを閉じる。本文を保持する読込失敗や外部スクロールでプレビュー内容を再初期化しない。

リンク先のファイル種類や存在確認をプレビュー可否の条件にしない。ソース位置を確実に対応付けられない場合の案内は右側だけに表示し、具体的な英語文言は実装時に整える。別の位置やリンク先内容へのフォールバックはしない。

## 状態遷移と終了

利用者向けの保持規則は[状態の保持と初期化](../../requirements/features/links-history.md#状態の保持と初期化)を正本とし、次の接続で実現する。

| きっかけ | 制御・状態遷移 |
|---|---|
| 開く | 対象世代の解析結果を用意し、空の検索で部品を組み立てる。親の購読を接続して共有ソースを設定した後、初期選択通知から先頭の範囲を表示する |
| 検索変更 | matcherの結果を`SetItems`へ渡す。同IDなら選択変更通知を出さず、強調・手動閲覧位置を維持する |
| 選択ID変更 | 世代と範囲を照合して`RevealRange`。不明なら`ShowUnavailable`とし、候補自体の選択・確定は妨げない |
| 選択が`None`になる／復活する | 消滅時は`ClearTarget`。復活時は先頭IDの通知から`RevealRange`を行い、消滅前の手動位置は復元しない |
| 半画面移動／ホイール | 閲覧位置だけを変え、入力・選択ID・強調範囲を維持する |
| 再描画のみ | 入力・選択ID・位置・フォーカスを設定し直さない |
| サイズ・フォント変更 | `FloatingPanel`が80%中央配置を再計算し、`SelectionPanel`は左右表示を維持する。`SourcePreview`は変更直前の上端のソース位置を基準に折り返しとキャッシュを再計算し、変更後もその位置を上端付近に保つ。文書端では有効範囲に補正する。ピクセル距離の単純保持や`RevealRange`の再実行はしない。入力・選択ID・強調・フォーカスを保持する |
| 実際の本文置換 | 別ファイルの成功・同ファイルの新内容採用などで文書管理の世代が変わったら、取消通知とは別経路で終了する。候補・範囲・プレビュー状態を失効させ、購読を破棄する。外部アプリからフォーカスを奪わない |
| 読込要求のみ／現文書を保持する失敗 | パネル・入力・選択・閲覧位置を維持する。ただしEnter確定で既に閉じていれば失敗しても再表示しない |
| 画像／Mermaid描画完了 | パネル状態を維持する |
| 外部CLIによる本文スクロール | 本文だけを移動し、プレビューの閲覧位置を維持する |
| 確定／取消 | パネル入力・選択・プレビュー状態・購読を破棄し、既存規則どおり本文へフォーカスを戻す。文書単位の解析結果は閉じただけでは捨てない |
| 再表示 | パネル固有状態を新規作成する。前回の検索・選択・閲覧位置を復元せず、同世代の解析結果のみ再利用できる |

## 未確定の描画詳細

全文スクロールと極端な長行の折り返しを実現する描画方式、左右の幅比率、位置不明案内の具体的な英語文言は、今回の合意では固定しない。全文閲覧・位置保持・入力保護の契約は維持し、これらの詳細は別途検討する。

## 検証観点

- 検索・並べ替え・選択変更で候補ID、リンク元ソース範囲、Enterの確定先が一致すること。
- 同名・同じ宛先の複数出現を一候補へまとめ、最初のソース範囲を保持し、検索・並べ替え後も最初の場所を表示すること。
- 通常のMarkdownリンク、参照形式の使用箇所、Markdown記法の画像混在リンク、複数行リンク、日本語、CRLFの位置対応。HTMLリンクとその断片が候補から除外され、プレビュー対象にもならないこと。
- 初期表示・候補変更時の縦中央配置と先頭・末尾での範囲補正、中央化用の余白なし、同じ候補での位置維持。
- 全文スクロール、長い行の表示上のみの折り返し、内容省略・閲覧不能な上限なし、行番号なし、対象ソース範囲の控えめな背景色強調。大きい文書でのコピー量と描画時間。
- 検索変更、取消と再表示、本文置換の後に古い範囲を使わないこと。閉パネルの通知や世代不一致のID・範囲を適用しないこと。非同期解析を導入した場合は逆順完了も確認する。
- 親の購読後に初期選択を通知し、同ID・再描画のみでは通知せず、候補消滅では`None`を通知すること。候補復活でリンク位置へ戻り、位置不明では前候補を残さないこと。
- サイズ・フォント変更で上端のソース位置を維持し、入力・選択・強調・フォーカスを初期化しないこと。共有ソースと文書単位の解析を再利用し、パネル終了時は固有状態と購読だけを破棄すること。
- プレビューで本文・履歴・検索・ツリー・監視・フォーカスを変えず、別ファイル取得・Web通信・画像取得・Mermaid生成を開始しないこと。
- リンク先が欠落・アクセス不能でもリンク元を表示でき、Enter時の失敗は従来どおり扱うこと。
- 既存のEsc、IME、候補なし、Enter、背景クリック、パネル終了規則の回帰確認。
- アプリ内表示領域を基準とする幅・高さ80%と中央配置、小さいウィンドウでも左右を常時表示することをGPUIで確認すること。
- `Ctrl+u` / `Ctrl+d`の半画面移動、プレビュー上のホイールの作用範囲、本文への非伝播、検索欄フォーカス維持を確認し、Windows実機で日本語IMEの優先、DPI、最小ウィンドウ、長い行を確認すること。
