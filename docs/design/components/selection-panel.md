## 責務と技術選定

[リンク選択](../../requirements/features/links-history.md#キーボードによるリンク選択)には、リンク以外にも再利用できる共通の選択パネルを用います。

- ファジーマッチにはRustの`nucleo-matcher`を採用します。外部のfzfプロセスは使いません。
- パネルは`gpui-kit`経由の`gpui-component`を利用し、公開APIを薄く包む方針とします。入力・候補表示・選択・確定・取消・フォーカス制御を共通化し、リンクの抽出やリンクを開く処理は呼び出し側に残します。
- 照合処理は表示UIから分離し、候補の絞り込み・順位付けと一致箇所をパネルへ渡せるようにします。確定結果は安定した候補IDへ対応付け、表示順の変更で別の候補を開かないようにします。

## 公開APIと制約

現在使用する`gpui-component 0.9.0`のローカル依存ソースでは、次の公開APIを確認しています。API調査であり、この組み合わせの実行時の動作確認を示すものではありません。

| 用途 | 確認したAPI・制約 |
|---|---|
| パネルの開閉 | `WindowExt::open_dialog` / `close_dialog`と`Dialog` |
| 検索欄・候補一覧・選択 | `Command` / `CommandState` |
| 独自照合の接続 | `filterable(false)`で標準の部分一致を無効にし、`on_query`で独自照合・順位付けした候補を渡せる |
| 補足情報と一致箇所の描画 | `CommandItem::child`で候補行を独自描画できる |
| 確定と候補なし表示 | `on_confirm` / `empty` |
| Esc | 標準は非空の入力を消してから次のEscで閉じる。製品仕様の1回での取消に合わせた制御が必要 |
| IME | `Command`の確定処理自体には未確定文字の検査がない。変換確定のEnterで候補を実行しないための保護が必要 |
| フォーカス | Dialogの初期フォーカスはシェルへ移るため、最初の描画時だけ検索欄へ移す。閉じる際の復帰機構はDialog側にある |

`gpui-component 0.9.0`の公開API調査では、`TextView`の標準リンク一覧と各リンクの画面座標を取得するAPIは確認できていません。リンク選択は座標に依存しない一覧方式とします。

## 検証観点

実装時にはIME、フォーカス、Esc、並べ替え後の選択先、本文置換後の古い候補の無効化を確認します。
