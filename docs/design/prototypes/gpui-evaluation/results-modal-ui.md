# モードUIの検証結果

[全体像](index.md) · [実行方法](running.md) · [検証計画](verification.md)

## 対象

V-02の検索UIを、Normal / Search / Commandと下部2行の表示へ変更しました。対象は作業ディレクトリの未コミット変更です。依存関係の追加・更新はありません。

- `src/app.rs`：モード、編集中と確定済みの検索語、取消時の一致位置の復元。
- `src/ui.rs`：モード別のキー操作、IME未確定状態の確認、固定幅のモード欄、ファイル名、入力行。
- `src/ui/search.rs`：上流の解析器と表示テキストAPIによる、表示ブロックからの検索開始位置の取得。
- `src/ui/tests/modes.rs`：実際のGPUIウィンドウ・入力ハンドラーを使う結合テスト。

## 自動テストで確認したこと

- モード変更や長いファイル名でも、モード欄の幅、ファイル名の位置、状態行と入力行の高さが変わらない。
- 検索入力中は強調だけを更新し、表示位置を動かさない。
- Enterで検索を確定し、Escで直前の検索語と選択していた一致を復元する。
- 空入力の確定で直前の検索語を再利用し、履歴がない場合や一致がない場合はメッセージを表示する。
- 表示ブロック以降の一致を選択し、文末からは先頭へ循環する。Mermaidの非表示ソースを検索範囲に含めない。
- 文書が置き換わった後、取消で古い文書の一致位置を適用しない。
- `:q`のEnterでウィンドウを閉じ、Escと未対応コマンドでは閉じない。`:e`などは実装していない。
- IMEの未確定範囲を持つInputStateにEnterを送っても、Search・Commandを終了しない。確定文字に置き換えた後のEnterでは処理を実行する。
- Normalの`j` / `k`、半ページ・1ページ移動、`gg` / `G`がスクロールを行い、入力中の`j` / `n` / `N`は入力文字になる。

## 制約・未確認

- 「現在位置」は表示上端のブロックの先頭を基準にしています。TextViewの公開APIから、折り返し行の上端にある文字位置は取得できていません。長い段落・表を途中までスクロールした状態では、同じブロックの画面外の一致を選ぶ可能性があります。画面上端の文字位置からの厳密な検索は未対応です。
- ブロックの範囲は、TextViewと同じ上流解析器・Mermaid拡張を使って取得します。解析結果とスクロール位置の対応付けに独自のMarkdown行分割は使っていません。範囲は文書世代ごとにキャッシュします。
- 実際のWindows日本語IMEによる変換・候補選択の操作は未確認です。入力ハンドラーへの未確定範囲の設定によるテストで代替できた扱いにはしません。
- Search・Commandの配色と入力行の描画品質は実機で未確認です。各モードの切り替え・寸法はGPUI結合テストで確認しています。
- 基本描画全体、写真・Web画像の実際のロード、見出し移動、閲覧位置保持、履歴、Releaseの起動時間は、この変更では検証していません。
