# モジュール間のAPI契約

[検証サンプルの全体像](index.md)

## 確認状況と粒度

会話で合意した責務の境界と、概念的な入出力を整理します。下記の型名・イベント名は説明用です。具体的なRustの型とGPUIに対する実現方法がすべて確定した契約ではありません。

製品の検索条件、削除された閲覧箇所の扱いなど、未確認の振る舞いをサンプルの都合で確定しません。検証用の条件を置く場合は製品仕様ではなく試験条件として記録します。

## 共通データの区別

| 概念 | 意味と制約 |
|---|---|
| 文書の識別子 | 操作や結果がどの文書を対象とするかを識別する |
| 文書の更新世代 | 同じ文書でも異なる内容を区別する。範囲や非同期結果は対象世代と対応付ける |
| ソース範囲 | Markdownソース内の範囲。表示テキストの範囲として直接使用しない |
| 表示テキスト範囲 | 描画対象のテキスト内の範囲。検索・強調・一致への移動に使用する |
| 文書内の位置 | 読んでいる内容を指す位置。上端からのスクロール量だけで表さない |
| 画面上の位置 | 現在のレイアウトで測定した座標。永続的な文書内の位置として扱わない |
| 図の生成対象 | 生成要求と、その要求に対応する図の内容を識別する情報 |

範囲の単位、文字境界、座標系の具体的な表現は、採用するAPIに合わせて明文化します。変換できない位置は、別種の位置へ暗黙に置き換えず、対応不能として扱えるようにします。

## core：判断・計算

| 処理 | 入力 | 出力 |
|---|---|---|
| 本文検索 | 表示テキスト、検索条件 | 一致する表示テキスト範囲の一覧 |
| 位置の対応付け | 更新前後の文書、更新前の位置 | 更新後の位置、または対応不能 |
| ラベル割り当て | 選択対象のリンク一覧 | リンクとラベルの対応 |
| ラベル入力の絞り込み | ラベルの対応、入力文字 | 候補や選択結果 |

- 文書や範囲の対象が分かる情報を維持する。
- ファイル読み込み、GUI操作、外部プロセス実行は行わない。
- 位置対応付けが成立しない場合の製品上の表示方針は、このAPIだけで決めない。

## app：状態更新と要求の生成

概念的な入口は次の形です。内部関数の分割や具体的な列挙型は固定しません。

```rust
fn update(&mut self, event: Event) -> Update;
```

| 境界 | 内容 |
|---|---|
| 入力：操作 | 文書を開く、再読み込みする、検索する、表示位置を移動する、リンクを選択するなど |
| 入力：通知 | 文書読み込み完了・失敗、表示テキストや位置情報の取得、図の生成完了・失敗など |
| 出力：I/O要求 | 文書の読み込み、図の生成など |
| 出力：表示要求 | 強調範囲の変更、範囲の表示、閲覧位置の復元など |
| 読み取りAPI | 現在の文書、検索状態、選択状態、図の状態など、描画に必要な状態 |

- 表示・検索・図に関するアプリ状態の更新は`app`が担当する。GPUIの描画資源やレイアウト情報は`ui`が管理する。
- I/O要求を返すことと、そのI/Oが完了したことを区別する。
- 読み込みや図生成の結果が現在の要求に対応しない場合、現在の文書へ反映しない。
- 表示テキストの取得・レイアウト確定が非同期になる場合も、通知が対応する文書と世代を確認する。
- 将来の外部操作も同じ操作の入口に接続する方針だが、今回外部通信のAPIは実装しない。

## ui：描画とレイアウト

| 方向 | 内容 |
|---|---|
| appから受け取る | 描画用の状態と、強調・スクロールなどの表示要求 |
| appへ通知する | キーやリンクの操作、表示テキスト、リンクの位置、現在の閲覧位置 |

- 表示テキストは、Markdownの記法を含むソースと区別する。
- リンクの画面上の位置は、折り返しやスクロールによって変化する。文字ラベルは取得時のレイアウトに対応させる。
- GPUIの型・ハンドルを`app`や`core`の契約に含めない。
- 閲覧位置の取得・復元やリンク位置の取得に必要な情報が標準APIで得られない場合、その制約を検証結果として残す。

## infra：ファイル・外部プロセス

| 処理 | 入力 | 出力 |
|---|---|---|
| 文書読み込み | 対象ファイルと要求の識別情報 | 対象を識別できる読み込み結果、またはエラー |
| Mermaid生成 | 図のソース・描画条件・要求の識別情報 | 対象を識別できる生成結果、またはエラー |

- I/Oは`main`から実行し、完了後に結果を`app`へ通知する。
- 実行できない場合や失敗した場合は、呼び出し元が原因を確認できる情報を返す。
- `infra`は表示状態を直接変更せず、古い結果の採否や図の非表示を判断しない。
- 製品のキャッシュ保存・ログ管理のAPI全体は、今回の契約に追加しない。

## 重要な異常系とテスト境界

| 条件 | 確認すること | 主な検証先 |
|---|---|---|
| 文書切り替え後に以前の読み込みが完了 | 以前の結果で現在の文書を置き換えない | appの状態更新テスト |
| 図の変更後に以前の生成が完了 | 古い図を現在の内容として表示しない | appの状態更新テスト |
| ソース更新後に以前の表示範囲が届く | 異なる世代の範囲を現在の文書へ適用しない | appとuiの結合テスト |
| 日本語や同じ文字列の複数出現 | 検索結果が対象テキスト内の正しい範囲を指す | coreの単体テストとuiの結合テスト |
| mermaid-cliがない、または生成に失敗 | 原因を取得でき、本文の描画を妨げない | infraとapp・uiの結合テスト |

具体的な確認手順と記録方法は[検証計画](verification.md)を参照してください。
