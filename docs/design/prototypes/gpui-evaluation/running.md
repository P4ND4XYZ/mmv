# 初期サンプルの実行

[検証サンプルの全体像](index.md) · [検証計画](verification.md) · [初期実装の検証結果](results-initial.md) · [Mermaidの検証結果](results-mermaid.md) · [モードUIの検証結果](results-modal-ui.md)

## 実装した範囲

V-01（基本描画）・V-02（本文検索）向けの初期サンプルに、V-05（Mermaid）の検証用実装を追加しています。リポジトリルートの1つのcrateで動かします。製品本体の実装や、描画基盤の採用決定ではありません。

- Markdownの描画はgpui-componentの`TextView`を使用します。Mermaidの差し込みには公開の拡張APIを使い、Markdown全体の独自解析器・描画器は追加していません。
- 日本語、表、チェックリスト、リンク、Rust・JSONのコードブロック、ローカル画像とWeb画像を含む[入力文書](fixtures/basic.md)を用意しています。
- シンタックスハイライトは`gpui-kit`の`syntect`機能で有効化しています。言語ごとの見た目は実機で確認する必要があります。
- ローカル画像はMarkdownファイルを基準に解決し、URLエンコードされた空白や`file://`を扱います。Web画像にはGPUIと同じスナップショットのHTTPクライアントを設定しています。埋め込みdata URLはこの初期サンプルの対象外です。
- ローカルファイルへのリンクをクリックすると、このウィンドウ内で文書を切り替えます。相対パスは表示中の文書を基準に解決し、空白のURLエンコード、絶対パス、`file://`に対応します。読み込み失敗時は元の文書を保持します。
- ファイル読み込みはバックグラウンドで実行します。読み込み要求と文書に世代を付け、古い読み込み結果や表示テキストを現在の文書に適用しません。
- 読み込み失敗は画面に表示し、再読み込み失敗時は直前の文書を保持します。UTF-8（BOM付きも可）を試験条件とし、他の文字コードは読み込みエラーにします。

V-03（文字ラベルによるリンク選択）・V-04（閲覧位置保持）は今回の対応対象外です。V-05でも閲覧位置保持は実装しません。V-06（Releaseでの起動時間計測）は未実施です。正式なCLI、ファイル監視、Named Pipe、履歴、永続キャッシュも実装していません。

コードは`src/main.rs`が初期化とI/O要求の実行、`src/app.rs`が世代・検索・図の生成状態、`src/core.rs`が検索と画像・リンク先のパス解決の計算、`src/infra.rs`がファイル読み込み、`src/ui.rs`がGPUI描画・入力を担当します。MermaidのCLI実行は`src/infra/mermaid.rs`、Windows Jobは`src/infra/mermaid/process.rs`、Markdown拡張は`src/ui/mermaid.rs`、GPUI結合テストは`src/ui/tests.rs`にあります。

## 環境と依存関係

WindowsのMSVC版Rust、Visual StudioのC++開発ツールとWindows SDK、CMakeが必要です。[上流のインストール案内](https://gpui-kit.com/docs/installation)も参照してください。

| 対象 | 選択した構成 |
|---|---|
| `gpui-kit` | `=0.9.0`、既定のcomponent/assetsと`syntect`機能 |
| GPUI | Kitが固定する`gpui-pre = 0.3.11`（Fastバックエンドは使用しない） |
| gpui-component / gpui-base | `0.9.0` |
| HTTPクライアント | `gpui-pre-reqwest-client = 0.3.11` |
| URL・パス解決 | `url = 2.5` |
| 引数解析 | `clap = 4`、`derive`機能 |
| 再現する依存関係 | ルートの`Cargo.lock` |

HTTPクライアントはWeb画像の取得に、`url`は文書相対URLとローカルパスの相互変換に使用します。依存関係はCargoで解決し、生成されたロックファイルを使用してください。上流の任意機能も含む解決条件により、`taffy = 0.15.0`と`unicode-properties = 0.1.3`が選ばれています。生成・vendorファイルの手動修正はしていません。

## 実行

リポジトリルートで実行します。

```powershell
# 指定したUTF-8 Markdownを表示
cargo run --locked -- "C:\documents\sample.md"

# ヘルプと操作の概要（ウィンドウは開かない）
cargo run --locked -- --help
```

`clap`で引数を解析し、表示するファイルを1つ必須で受け付けます。ファイル未指定・余分な引数・未知のオプションはウィンドウを開かずに終了コード2で終了します。`-h` / `--help`、`--version`は表示後に終了コード0で終了します。ファイル未指定時に`basic.md`を自動表示する機能はありません。ファイル指定はこの検証サンプルの入口であり、正式な製品CLIではありません。初回のビルドには依存関係のダウンロードとコンパイルが必要です。

### 操作と検索の試験条件

初期モードはNormalです。上部のファイル情報と常設の検索欄・件数・前後ボタンは置かず、下部を固定の2行にしています。

- 状態行：等幅フォントの固定幅モード欄とファイル名。モード欄の幅は96pxで、長いファイル名は省略します。
- 入力行：Searchでは`/検索語`、Commandでは`:コマンド`を表示します。Normalでは通常空欄で、読み込み中やエラーなどがある場合だけ表示します。
- 各行は文字の行高20px＋上辺の横線1pxです。モード変更や長い入力でも高さを変えません。

| モード表記 | モード欄の背景色 | 文字色 |
|---|---|---|
| NORMAL | 青 `#2563EB` | 白 `#FFFFFF` |
| SEARCH | 黄 `#FBBF24` | 濃いグレー `#111827` |
| COMMAND | 紫 `#7C3AED` | 白 `#FFFFFF` |

| 操作 | 動作 |
|---|---|
| マウスホイール | 本文をスクロール |
| Normalで`j` / `k` | 下／上へ本文1行程度スクロール |
| Normalで`Ctrl+d` / `Ctrl+u` | 下／上へ半ページ移動 |
| Normalで`Ctrl+f` / `Ctrl+b` | 下／上へ1ページ移動 |
| Normalで`gg` / `G` | ファイル先頭／末尾へ移動 |
| Normalで`/` | Searchへ移り、空の検索入力を開始 |
| Searchで文字入力 | 整形後の表示テキストを検索し、一致範囲を強調。スクロールしない |
| Searchで`Enter` | 検索を確定し、現在の表示ブロック以降の最初の一致へ移動してNormalへ戻る |
| Searchで空入力の`Enter` | 直前の確定済み検索語を再利用。直前の検索がなければエラー |
| Searchで`Esc` | 入力を破棄し、確定済みの検索語と選択していた一致を復元してNormalへ戻る |
| Normalで`n` / `N` | 次／前の一致を表示 |
| Normalで`:` | Commandへ移り、空のコマンド入力を開始 |
| Commandで`q`を入力して`Enter` | ウィンドウを閉じる。他のコマンドは未対応のエラーを表示してNormalへ戻る |
| Commandで`Esc` | 実行せずNormalへ戻る |
| Commandで空入力の`Backspace` | Normalへ戻る。文字がある場合は削除のみ行い、最後の1文字を削除した時点ではCommandを維持 |
| Normalで`F5` | 同じファイルを再読み込み。現段階では閲覧位置を復元しない |
| Webリンクをクリック | 既定のブラウザーで開く |
| ローカルファイルへのリンクをクリック | このウィンドウ内でファイルを開く。切り替え後の`F5`もそのファイルが対象 |
| 同一文書の見出しリンクをクリック | 未対応のメッセージを表示。見出し移動は未実装 |

Search・Commandの入力中はNormalのキー操作を実行しません。IMEの未確定文字が残る`Enter`では入力モードを終了せず、確定後の`Enter`で検索確定・コマンド実行を行います。

ローカルリンクは、[基本サンプル](fixtures/basic.md)をファイル引数で明示的に指定して起動し、「別のローカルMarkdownを開く」から試せます。移動先には戻るリンクと、読み込み失敗を試すリンクがあります。ローカルファイルはUTF-8のMarkdownとして読み込みます。別ファイルへのリンクに`#見出し`が付いていても先頭から開き、見出し位置への移動と戻る／進む履歴はまだ実装していません。

検索は大文字・小文字を区別するリテラル検索で、重複しない一致を列挙します。編集中の空の検索語は一致なしで、空のまま確定した場合は直前の検索語を再利用します。確定時に表示ブロック以降で一致が見つからなければ先頭へ循環します。次／前への移動も端で循環します。これらは検証用の条件であり、未合意の製品検索仕様を確定するものではありません。

**検索開始位置には制約があります。** GPUIの公開APIで取得できるのは表示上端のブロックです。同じ上流解析器が返すブロックのソース範囲を表示テキストの範囲へ変換し、そのブロックの先頭から検索します。折り返した長い段落や表を途中までスクロールしている場合、画面より上に隠れた同じブロック内の一致を選ぶ可能性があります。画面上端の文字位置からの厳密な検索は未対応です。位置対応付け用のブロック範囲は文書世代ごとにキャッシュします。

`rendered_text()`が返すUTF-8バイト範囲で検索し、そのスナップショットに対応する強調・移動APIへ渡します。ソースの記法やリンク先URLを検索対象の本文とは扱いません。`reveal_range`の成功は要求を受け付けたことを表し、実際の画面内表示は結合テストと実機で別に確認します。

## Mermaidの試験条件

Node.jsと、npmでグローバルインストールした`mermaid-cli`が必要です。`mmdc --version`だけでなく、実際の図生成が成功することを確認してください。検証環境では`12.0.0`を使用しています。

```powershell
# フローチャート・クラス図・ER図（日本語ラベルあり）
cargo run --locked -- docs/design/prototypes/gpui-evaluation/fixtures/mermaid.md

# 構文エラー時の本文表示と標準エラー出力
cargo run --locked -- docs/design/prototypes/gpui-evaluation/fixtures/mermaid-invalid.md
```

- 上流のMarkdown解析器が認識した言語名`mermaid`のコードブロックだけを、公開`MarkdownPlugin` APIで独自ブロックへ置き換えます。独自のMarkdown解析器や上流改修は追加していません。
- 拡張APIの設定後にソースを渡すため、未生成・失敗時の代替として図のソースコードを表示しません。検索対象にも含めません。通常のコードブロックは引き続き表示します。
- 本文を先に表示し、バックグラウンドで図を1件ずつ生成します。PNG、白背景、倍率2、`Yu Gothic UI, sans-serif`、`securityLevel: strict`を試験条件とします。
- 完成した図は本文中へ追加し、画像の縦横比を維持して表示領域に収めます。図のラベルは画像であり、本文検索・文字選択の対象ではありません。
- 成功した再読み込みで図の状態と描画資源を置き換え、文書世代・ソース位置・図の内容が一致しない古い生成結果は採用しません。実行中の旧要求はそのまま完了を待つため、新しい図の生成開始が遅れる場合があります。
- 生成失敗時はその図を非表示にし、対象ファイル・ブロックのUTF-8バイト位置・失敗理由を標準エラーへ出力します。本文と他の図は表示し続けます。画面ではNormalの入力行にも失敗理由を表示します。完了・待機／生成中・失敗の件数の常設表示はありません。
- 図ごとの待機上限は45秒です。Windowsでは生成プロセスをkill-on-close Jobへ所属させ、タイムアウトやビューアー終了時に子プロセスが残らないようにします。
- WindowsではPATH上の`mmdc.exe`、または標準のnpmグローバル`mmdc.cmd`に対応します。npmの場合はNodeのCLIエントリーポイントを直接起動し、Markdownやパスをシェルへ渡しません。独自ラッパーやnpm以外の配置は未検証です。
- 一時生成物はメモリへ読み込んでから削除します。終了をまたぐキャッシュはありません。同じ図も再読み込み時には再生成します。生成途中のアプリ終了などでは一時ディレクトリが残る可能性があります。

**閲覧位置の復元は行いません。** 図の追加でレイアウトが変化します。製品の位置保持・永続キャッシュ・ログ管理要件を、この試験条件で変更したわけではありません。

## 自動チェック

```powershell
cargo fmt --check
cargo check --locked
cargo test --locked --features ui-tests
cargo clippy --locked --all-targets --features ui-tests -- -D warnings

# 実際のmermaid-cliが必要な結合テスト（通常はスキップ）
cargo test --locked --features ui-tests real_ -- --ignored --nocapture
```

- 引数解析のテストは、ファイル指定、引数不足・過剰・未知のオプションの拒否、ヘルプ・バージョンの正常終了を確認します。
- 通常のテストはUTF-8検索、画像・リンク先のパス解決、世代管理、失敗後の状態、実ファイル読み込み、図の直列実行と古い結果の除外、外部プロセスの起動失敗、Windows Jobによる停止を確認します。
- `ui-tests`はGPUIのテスト用ウィンドウで、実際のMarkdown表示テキスト、モードごとの入力とキーの分離、検索の確定・取消・再利用、検索結果への移動、IME未確定中のEnter、`:q`と取消・未対応コマンド、下部2行とモード欄の固定サイズ、ローカルリンクのクリックによる読み込み要求と表示切り替え・失敗時の文書保持・切り替え後の再読み込み、Mermaidの検出・非表示・後付けレイアウト・検索範囲を確認します。実ツールを使うテストでは3種類の図を生成し、GPUIでPNGをデコードします。GPUを使う実機の描画品質や日本語IMEの動作確認の代わりにはなりません。
- 画像のロード結果、コードの色、チェックリストの読み取り専用性、折り返しと強調の位置は[検証計画](verification.md)に沿って目視確認します。

## 計測用の参考出力

本文のソースに対応する解析結果が描画された最初のフレームで、標準エラーに次の値を1回出します。

```text
first_content_paint_from_main_ms=...
```

これはRustの`main`開始からGPUIのpaintコールバックまでの参考値です。OSのプロセス生成からの時間ではなく、画面への提示完了、画像ロード完了も保証しません。V-06のRelease起動時間計測を完了した扱いにはしません。

## 次段階のAPI上の制約

`0.9.0`の公開API調査では、`TextView`の標準リンク一覧と各リンクの画面座標を取得するAPIを確認できていません。`on_link_click`はURLとクリック通知を提供しますが、表示中のリンクを列挙する機能ではありません。

`gpui-base::text::editor_host`には独自ホスト向けの葉の座標収集APIがありますが、標準`TextView`のリンクと表示テキスト範囲に対応付ける一式のAPIとしては確認できていません。インラインプラグインでリンクを独自要素に置き換える方法も、通常のリンクの折り返し・選択を変える可能性があり、V-03の成功として扱いません。

V-03は今回の対応対象外です。将来対応する場合は、上流APIの追加調査・拡張を検討するか、独自ホストの追加実装を検証対象に含めるか改めて判断します。大幅な独自改修や製品要件の変更は、このサンプルには含めていません。
