# テスト設計と実施順序

[設計全体像に戻る](index.md)

## 目的と対象

既存プロトタイプの振る舞いを守ってモジュールを分割し、その後、製品仕様の変更を機能単位で検証します。初期版全体の未実装APIに対するテストを一括作成するのではなく、現在のAPIで追加できるケースと、新しい契約の実装時に追加するケースを分けます。

この文書は検証方法と期待結果を定義します。ケースの記載や既存テスト名の参照は、テストの実行・成功を意味しません。

## 検証の境界

| 対象 | 単体テスト | 結合テスト・実機確認 |
|---|---|---|
| core | 文字列・値を入力した検索、リンク解決、見出しID計算 | Markdown解析結果と描画位置の対応 |
| app | 操作・完了通知に対する状態、要求、応答の変化 | UIとI/Oの要求・完了通知の接続 |
| cli | 引数解析、コマンドへの変換、与えられた基準ディレクトリによるパス解決、結果の終了コードへの変換 | 実行プロセスの出力と終了、実際のカレントディレクトリ |
| infra | I/Oから独立した通知の判定、期限・起動方針・ログ整理の判断 | 実ファイル、監視、Pipe、ロック、子プロセス、ログの書き込み |
| ui | 独立した計算がある場合の値の変換 | GPUIでの入力、レイアウト、強調、位置復元、モード表示 |

実際のスクロール、入力欄の文字列、IME、Windowsの前面ウィンドウを、`app`の単体テストだけで確認した扱いにしません。特にCommandの文字列とIME状態はUI側にあり、単体テストのためだけに`app`へ複製しません。

## モジュール分割前に補う単体テスト

最初は`src/app.rs`の既存APIを使います。本文の読み込み結果と表示テキストの通知はテストから与え、実ファイルやGUIを起動しません。分割後は対応する責務のテストへ移しますが、ファイル配置や型名そのものを期待値にしません。

| ID | 条件・操作 | 期待結果 | 追加方法 |
|---|---|---|---|
| U-01 | 文書と検索結果がある状態で別ファイルの読み込みを開始し、まだ完了させない | 現在のパス・本文・検索結果を保持し、読み込み中になる | 読み込み開始時点を確認する独立ケース |
| U-02 | 表示中の文書がある状態で要求A、要求Bを開始し、Bを失敗させた後でAを成功させる | 元の文書とBのエラーを保持する。Aの成功で文書やエラーを上書きせず、待機状態も復活させない | 既存の古い完了のテストを拡張する |
| U-03 | 検索語を確定し、再読み込みまたは別ファイルの読み込みを成功させ、新しい表示テキストを通知する | 確定済み検索語で新しい本文の一致を更新し、古い一致範囲を再利用しない。Normal・Commandでは同じ検索語を使う | パス・モードの違いは同じ検証目的のデータとして扱う |
| U-04 | 確定済み検索語とは異なる語をSearchで編集中に、本文の読み込みを成功させる | Searchを維持し、編集中の語で新しい本文の一致を更新する。確定済み検索語へ戻さない | Search中の更新として独立ケース |
| U-05 | 確定済み検索語がある状態で空入力のSearchへ入り、本文を更新する | 入力を空のまま維持し、新しい本文に確定済み検索語が含まれていても一致なしとする | 空入力の意味を確認する独立ケース |
| U-06 | SearchまたはCommand中に読み込みを失敗させる | 入力モード、本文、検索結果を保持し、読み込みエラーを記録する。Searchでは編集中の検索語も失わない | モード違いを同じケースのデータとして扱う |
| U-07 | 複数一致の2番目を選択した後、同じ世代・同じ表示テキストを再通知する | 再通知によって選択を先頭へ戻さない | 同一スナップショットの再通知として独立ケース |

U-03では、たとえば`target target`で検索語`target`を確定し、更新後の表示テキストを`prefix target`とした場合、一致はUTF-8バイト範囲`7..13`の1件とします。U-04では、確定済み検索語`old`、編集中の語`edit`、更新後の本文`edit edit old`に対し、一致は`0..4`と`5..9`です。

読み込み成功の通知だけでなく、現在の世代に対応する表示テキストの通知まで行って検索結果を確認します。検索語の保持は、結果や検索語の再利用操作から確認できるなら、そのためだけの公開getterを追加しません。

現在のAPIで移動要求を観測できないケースについて、単体テストだけで自動スクロールの有無を保証しません。後述の位置方針のテストとGPUI結合テストで補います。

## 既存テストの扱い

以下は既存テストを維持する範囲です。同じ契約を確認するケースを、モジュールが増えたという理由だけで重複追加しません。

| 既存の配置 | 主な契約・参照するテスト |
|---|---|
| `src/core.rs` | UTF-8範囲、大小文字を区別する重複なしリテラル検索、空文字・一致なし、画像とリンクのパス解決 |
| `src/app.rs` | `stale_success_and_failure_cannot_replace_the_latest_request`、`reload_failure_keeps_the_displayed_document` |
| `src/app.rs` | `search_preview_cancel_and_empty_commit_keep_the_confirmed_query`、`cancel_does_not_restore_a_match_index_from_a_replaced_document`、`search_rejects_old_rendered_text_and_resets_after_replacement` |
| `src/app.rs` | `diagrams_run_serially_and_failure_does_not_hide_the_document_or_retry`、`old_diagram_results_release_the_worker_without_touching_the_new_document` |
| `src/main.rs` | ファイル引数、日本語・空白のパス、不足・余分・未知の引数、ヘルプ・バージョン。正式CLIへの変更時に拡張する |
| `src/infra.rs` | 実ファイルを使うUTF-8・BOM・不正文字コード・ファイル不在の結合テスト |
| `src/ui/tests.rs`、`src/ui/tests/modes.rs` | 表示テキスト、検索、入力モード、IME、下部2行、リンク、MermaidのGPUI結合テスト |

`local_links_resolve_from_the_displayed_document_and_strip_fragments`は現行プロトタイプの契約です。見出し対応を追加する際は「フラグメントを捨てる」という期待値を変更し、ファイルと見出しIDを保持する製品仕様を検証します。分割だけの段階で先に意味を変えません。

## 文書操作の共通処理に追加する単体テスト

新しい操作・出力の契約を定めた後、対象機能の実装と組み合わせて追加します。未実装APIを参照したコンパイルエラーを、振る舞いの失敗確認とは扱いません。

| ID | 対象 | 期待する振る舞い |
|---|---|---|
| D-01 | 操作の分類 | 初回・別ファイル・再読み込み・見出し・履歴で、読み込みの要否、位置方針、履歴の扱いを区別する |
| D-02 | 再読み込みの距離 | 開始時240、成功時の置換直前480なら、復元要求は480。開始時の距離へ戻さない |
| D-03 | 読み込み失敗 | 文書・履歴を変更せず、新しい文書への位置移動を要求しない |
| D-04 | 位置要求の世代 | 本文解析・レイアウト待ちの間に別文書へ切り替わった場合、古い位置要求を失効させる |
| D-05 | 入力元とモード | 外部操作はSearch・Commandでも受け付け、モードの変更や入力の確定・取消を要求しない |
| D-06 | 検索結果の更新 | 再読み込み・切り替えによる検索結果更新では、一致への移動を要求しない。操作が指定した先頭・距離・見出しへの移動とは区別する |

単体テストでは、距離480などの値やレイアウト準備完了の通知を明示的に入力し、採用する位置方針を確認します。実際のレイアウト後に480へ移動できること、文書が短くなった場合の末尾への収まり、画面外ブロックを含む距離の取得はGPUI結合テストで確認します。

位置要求の失効などをUI側で管理する場合は、その判定を担当する箇所で検証します。単体テストを成立させるためだけに、GPUIの状態や実際のスクロール処理を`app`へ移しません。

## 後続の実装時に追加する単体テスト

| 機能 | ケースの選定 |
|---|---|
| 履歴 | 読み込み成功時だけ追加・現在位置を変更する。失敗では維持する。戻った後の新規移動で進む側を破棄する。通常スクロール・検索移動・再読み込みでは項目を増やさない |
| 見出し・リンク | 同一・別ファイルのフラグメント保持とデコード、日本語・装飾・重複見出し・番号付きIDとの衝突、見出し不在時の先頭移動と通知 |
| 自動更新 | 古い監視対象の通知を除外する。別ファイルへの切り替え待ちを元ファイルの通知で取り消さない。監視対象の変更は文書採用時だけ行う |
| 正式CLI | `open`と省略形の同等性、全操作の解析、サブコマンドと同名のファイルの明示、日本語・空白、引数エラー、終了コード、CLI側の基準パス |
| 要求・応答 | 要求IDと読み込み結果を対応付ける。完了順が逆転しても応答先を混同しない。表示へ採用しない古い要求にも読み込み結果を返す |
| 起動判断 | 接続可能なら既存GUIを使う。未起動の移動操作では起動しない。起動済みだが接続不能な場合に別GUIを起動しない |
| 待機制御 | 時刻を明示的に与え、接続5秒・起動30秒・読み込み30秒の期限と段階の切り替えを確認する。再試行で期限を延長せず、タイムアウト後に操作を自動再送しない |
| ログ | 同じ生成失敗の大量記録を抑える判断、容量上限とバックアップ世代に応じた整理の判断を確認する |

通知の集約やログ整理などに独立した判断処理がある場合に単体テストを置きます。単体テストのためだけにOS API全体のモックや汎用のI/Oフレームワークを作りません。永続キャッシュのテストは初期版には追加しません。

## 結合テスト・実機確認で補う範囲

- GPUI：長い段落・表・画像を含む距離復元、短縮後の末尾制限、レイアウト待ちと世代の対応、見出しの実際の表示位置。
- GPUI：Search・Command中の本文更新・外部操作で入力欄と文字列を保持すること。検索更新だけでは移動せず、CLIが指示した移動は実行すること。
- 実ファイル：上書き・置換保存、監視対象切り替え、読み込み失敗。ファイルの同一性はWindowsの実ファイルシステムでも確認する。
- Pipeとプロセス：要求の境界、切断、起動競合、単一起動、GUI終了、実際の待機上限とCLI終了コード。
- ログと一時生成物：ローテーション、保存失敗時の標準エラー出力、生成物の削除、異常終了後の整理。
- Windows実機：実際の日本語IME、初回起動と外部操作でのフォーカス維持、画像・コード・チェックリストの表示。

## ツリーオープンと英語GUIの検証

- app：同一キーで世代・位置・検索・履歴を維持し、別文書では先頭と履歴追加。CLI等との交錯・逆順完了・同一キーによる先行要求の失効・失敗時の保持を検証する。
- infra：実ファイルの`.MD`、別表記のDocumentKey、不正UTF-8へ変更後の同一キー未読、削除・ファイル種別／祖先junction差し替え、ルート外・`..`拒否を検証する。ルートより上の検査や原子的保証は要求しない。
- GPUI：Enter／lと→の違い、フォルダー既存操作、非Markdown・既知reparseの無操作、別文書成功時の先頭・履歴追加・本文へのフォーカス移動、同一キー成功時の未読・本文へのフォーカス移動のみ、失敗時の文書・位置・履歴・ツリーフォーカス保持と既存英語通知、古い完了によるフォーカス移動の抑止、同一ルートの展開・カーソル・スクロール保持を確認する。
- GUI文言：通知一覧とパネル種類・空表示・accessibility・設定・読み込み・解析・検索の英語を検証する。未知の非英語OS原因を与えても固定英語になり、詳細ログには原因が残ること、本文・名前・パス・入力は翻訳されないことを確認する。
- Windows実機：実IME・OSフォーカス・最小幅とDPI、ACL・ロック・UNC切断・クラウド固有reparseは自動テストと分けて確認する。

## 実施順序とチェック

### 最初の変更単位

1. 作業ツリーの既存変更と対象仕様を確認する。
2. 既存テストを実行し、基準となる結果と環境依存の未実施項目を把握する。
3. U-01からU-07の不足ケースを追加し、既存の契約を検証する。既存テストの拡張で済むケースは重複作成しない。
4. テストが仕様違反を示した場合は、期待値を実装へ合わせず、修正とモジュール分割を別の変更単位にする。
5. モジュールを小さく分割し、各まとまりで関連テストを実行する。
6. 分割後にGPUI結合テストとClippyを実行し、UIとの接続も確認する。

機能追加はこの分割と切り分け、D-01以降と後続機能のケースを対象範囲に応じて追加します。失敗を確認する場合は、契約に対するアサーションの失敗を確認し、構文エラーや環境不足とは区別します。

### コマンド

リポジトリルートで実行します。

```powershell
# 初期の基準確認。実CLI用のignoredテストは含まない
cargo test --locked --features ui-tests -j 4

# appの単体テストを追加・分割したときの最小範囲
cargo test --locked app::

# coreの変更時
cargo test --locked core::

# UIの分割・接続変更後のGPUI結合テスト
cargo test --locked --features ui-tests ui::

# まとまった変更後の書式と静的チェック
cargo fmt --check
cargo clippy --locked --all-targets --features ui-tests -- -D warnings

# 実際のmermaid-cliが必要な範囲を変更した場合だけ明示的に実行
cargo test --locked --features ui-tests real_ -- --ignored --nocapture
```

フィルターは分割後のモジュール配置に合わせて調整します。単一ケースの修正後はそのケースと関連する最小範囲を先に確認し、広いチェックを毎回繰り返しません。

既存の`#[test]`とGPUIのテスト基盤を使用し、このテスト計画のための依存追加・更新は行いません。時刻と非同期完了順は必要な境界で制御し、実時間のsleepや偶然の競合に頼らない単体テストにします。

実施結果は作業報告で、実行したコマンド、成功・失敗、既存の失敗、環境依存のスキップ、実機未確認を分けて伝えます。この設計文書へ実行履歴や進捗表を追加しません。

## リンク選択のソースプレビュー

左右一覧・プレビューと下部入力欄の変更では、[リンク選択の仕様](../requirements/features/links-history.md#配置とソースプレビュー)と[選択パネル設計の検証観点](components/selection-panel.md#検証観点)に従い、次を確認する。

- 候補抽出・位置対応：通常のMarkdownリンク、参照形式の本文中の使用箇所、Markdown記法の画像混在リンク、複数行リンク、日本語・CRLFを対象とする。HTMLリンクとHTMLアンカーの断片は既存の候補表示からも除外され、プレビュー対象にならないことを確認する。本文上のHTMLリンクのクリック動作は今回の変更対象外とする。
- 候補の同一性：同名・同じ解決後の宛先をまとめた候補が最初の出現のソース範囲を保ち、検索・並べ替え・選択後も候補IDとEnterの確定先が対応すること。
- GPUIの配置：別OSウィンドウではなく、アプリ内表示領域の幅・高さそれぞれ80%で中央に重なること。モニター寸法に依存せず、ウィンドウサイズが小さくても左の候補一覧・右のプレビュー・下部入力欄を表示すること。
- GPUIの位置・表示：初期選択・候補変更でリンク記述位置を縦中央に置き、文書先頭・末尾では余白を追加せず有効範囲へ補正すること。同じ候補の検索変更・再描画ではスクロール位置を維持すること。対象リンクのソース範囲を控えめな背景色で強調し、行番号は表示しない。Markdown全体の構文色分けは検証要件に追加しない。
- 全文閲覧：長い行を表示上のみ折り返し、内容省略や閲覧不能な上限なしで文書の先頭から末尾までスクロールできること。極端に長い行や大きい文書でもこの契約を維持すること。
- 入力の分離：`Ctrl+u` / `Ctrl+d`でプレビューを半画面上／下へ動かし、プレビュー上のホイールもプレビューだけに作用すること。本文へ伝播せず検索欄フォーカスを保ち、IME変換操作を優先すること。実際の日本語IME・DPI・最小ウィンドウはWindows実機で補う。
- 副作用・寿命：リンク先取得・Web通信・画像取得・Mermaid生成や本文・閲覧位置・履歴・本文検索・ツリーの変更がないこと。検索対象は表示名とリンク先のまま、位置不明時は誤った位置やリンク先内容へフォールバックしないこと。文書世代変更後は古い範囲を使わず、本文置換時の終了、本文を保持する読み込み失敗や外部スクロール時の継続、既存の確定・取消・IME保護を回帰確認する。

仕様と設計の更新だけでは、実装やこれらの検証が完了したとは扱わない。
