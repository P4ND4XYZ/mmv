# my-markdown-viewer 詳細設計

## 対象と前提

Windows向けの読み取り専用ビューアーを、既存の[GPUIプロトタイプ](prototypes/gpui-evaluation/index.md)から段階的に作成します。1つのcrateと現在の責務分担を維持し、Markdownの独自解析器・描画器への置き換えは行いません。

初期版には、自動更新、スクロール距離の維持、見出し移動、履歴、正式CLI、単一起動、Named Pipeによる外部操作、Mermaidの非同期生成とエラーログを含めます。Mermaidの永続キャッシュは後続版へ分離します。

この文書群では、全体構成とモジュール境界、実装順序とテスト設計、最初に共通化する文書操作とCLI連携の契約を扱います。後続段階のファイル監視・ログ管理については責務と検証範囲を示し、個々のAPIや内部関数まで固定しません。

## 構成と責務

| 対象 | 責務・境界 | 既存の主な配置 |
|---|---|---|
| 起動・接続 | CLIとGUIの役割を選び、要求の配送とI/Oの開始・完了通知を接続する。文書や履歴の採否は判断しない | `src/main.rs` |
| core | 検索、リンク解決、見出しIDなどの計算。GPUIと実際のI/Oに依存しない | `src/core.rs` |
| app | 現在の文書、要求の世代、入力モード、検索、履歴を管理し、I/O要求と表示要求を作る | `src/app.rs` |
| infra | 文書読み込み、パスの同一性確認、ファイル監視、Named Pipe、単一起動制御、Mermaid生成、一時生成物とログの管理 | `src/infra.rs`、`src/infra/` |
| ui | 描画と入力、スクロール距離の取得・復元、見出しと検索一致への移動。GPUIの型・ハンドルをこの層に閉じ込める | `src/ui.rs`、`src/ui/` |

既存と同様に、`app`は`core`へ依存し、`ui`と`infra`は`app`の契約を使用します。起動・接続部分が各層を組み合わせます。必要な機能の追加に合わせてモジュールを分割し、先行してcrate全体を再構成しません。

内部の分割方針と状態の所有者は[モジュール構成と責務境界](components/module-boundaries.md)、文書操作の契約は[文書操作と閲覧状態](components/document-operations.md)、起動と通信は[CLI・単一起動・外部操作](components/external-control.md)を参照してください。

## 主要な処理・データの流れ

1. キー入力、リンク、監視通知、CLI要求を、操作元を識別できる文書操作・移動操作へ変換する。
2. `app`が文書の切り替え方、履歴の扱い、表示位置の方針を決める。読み込みが必要なら要求を発行する。
3. 起動・接続部分が`infra`で読み込みを開始し、完了を`app`へ返す。UIスレッドでファイルやPipeの待機を行わない。
4. `app`が現在も有効な結果だけを採用し、文書と履歴を更新する。CLIにはその要求に対応した読み込み結果を返す。
5. `ui`が新しい本文を設定し、対象世代のレイアウトが利用可能になってから表示位置を適用する。検索結果の再計算だけでは移動しない。
6. Mermaidは本文表示と独立して生成し、有効な結果だけを後付けする。生成失敗は画面に出さずログへ記録する。

## 共通の設計方針

- 読み込み要求、採用済み文書の世代、CLIの要求IDを区別する。古い結果の表示への適用防止と、要求元への応答完了を混同しない。
- ソース範囲、表示テキスト範囲、スクロール距離を区別する。再読み込み・履歴には距離、検索には表示テキスト範囲、見出しには解析結果に対応する位置を使う。
- 文書と履歴の変更は読み込み成功時に確定する。失敗では元の本文・位置・履歴を残す。
- キーボードのNormal専用制約は入力の入口で判定する。共通のスクロール・履歴処理自体をNormal限定にせず、外部CLIからは入力中も実行できるようにする。
- 外部CLI操作と自動更新では入力モードと入力文字列を維持する。検索・コマンドの確定、取消、入力欄へのフォーカス変更を文書更新に伴って実行しない。
- Mermaidの生成形式はプロトタイプのPNGを流用する。初期版では永続キャッシュ、キャッシュキー、容量整理、利用日時のJSON管理を追加しない。一時生成物の削除とログは対象に含める。

## プロトタイプからの変更点

| 既存の実装 | 製品での変更 |
|---|---|
| 単一ファイル引数からGUIを直接起動し、アクティブ化する | 正式CLIとGUIの役割を分離し、単一起動と非アクティブ起動を追加する |
| 再読み込みで`TextViewState`を作り直し、位置を戻さない | 文書の置換と表示位置の適用を分け、レイアウト後に距離を復元する |
| ファイルリンクのフラグメントを捨てる | 見出しIDを保持して移動し、履歴を管理する |
| UIのスクロール処理内でNormal以外を拒否する | 入力元の制約と共通の移動処理を分ける |
| Mermaid失敗を標準エラーと下部入力行に出す | 下部入力行には出さず、指定先のローテーションログへ記録する |

## 実装順序と段階ごとの検証

### 最初の作業単位

製品機能を追加する前に、既存テストの基準確認、不足する単体テストの追加、振る舞いを変えないモジュール分割を行います。まず[テスト設計](testing.md)の「モジュール分割前に補う単体テスト」を対象にし、新機能のAPIや初期版全体のテストを一括作成しません。

着手時は[要求・要件](../requirements/index.md)、この全体設計、[モジュール構成](components/module-boundaries.md)、[テスト設計](testing.md)を読み、その後、対象に応じて文書操作・外部操作の詳細を参照します。既存の作業ツリー変更を確認して保持し、小さな変更単位ごとに検証します。

### 機能追加の順序

| 順序 | 実装単位 | 完了時に確認すること |
|---|---|---|
| 1 | 文書操作の共通処理と要求・結果の契約 | 別ファイル、再読み込み、見出し、履歴を区別でき、失敗・古い完了で状態を壊さない |
| 2 | スクロール距離の取得・復元 | 長い段落・表・画像を含む文書で距離を復元し、短縮時は末尾に収まる |
| 3 | 自動更新 | 保存とF5が同じ再読み込み処理を使い、置換保存、監視対象変更、入力中の更新に対応する |
| 4 | 見出しリンクと履歴 | 日本語・重複見出し、戻る／進む、失敗時の履歴維持、短縮後の位置復元が動く |
| 5 | 正式CLI、Named Pipe、単一起動、外部操作 | 読み込み結果・終了コード・待機上限・パス基準・非アクティブ操作・入力維持を満たす |
| 6 | Mermaidのログ管理と一時生成物の整理 | 図の失敗を画面に出さず記録し、ローテーション・書き込み失敗・終了後の整理に対応する |
| 7 | 機能横断の確認 | 検索中の更新、履歴先の変更、非同期完了順の逆転、同時CLI操作、日本語IMEと描画を確認する |

第1段階では、後の構造変更を避けるため、GPUIでの距離取得・復元、見出しへの移動、Windowsでの非アクティブ起動、CLIとGUIの応答接続を小さく先行検証します。これは機能全体を第1段階で実装する意味ではありません。

各段階で必要な単体・結合テストを追加します。`core`は値の計算、`app`は状態と完了順、`infra`は実ファイル・Pipe・プロセス、`ui`はGPUIのレイアウトと入力を確認します。Windows実機でのIME・フォーカス・画像の表示確認は、自動テストとは分けます。ケースの選定、既存テストの扱い、実行コマンドは[テスト設計](testing.md)を参照してください。

永続キャッシュはこの順序の初期版には含めません。Vimium風リンク選択、内容基準の位置復元、画面上端の文字位置からの厳密な検索も追加しません。Release起動時間の計測は必須にしません。
