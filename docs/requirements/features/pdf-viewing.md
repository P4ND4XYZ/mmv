# PDF表示

[全体像に戻る](../index.md)

## 基本の流れ

1. CLI・起動時の`mmv open FILE`／`mmv FILE`、ファイルツリーのEnter／`l`、Markdown内のローカルPDFリンクから開く。
2. 読み込みとPDF解析が成功したら、本文領域へ幅合わせで表示する。
3. アプリ側のキー操作でスクロール・ズームし、別文書を開いたら同じ本文領域で切り替える。

ツリーの表示対象・開ける拡張子・reparse pointの制限は[ファイルツリー](file-tree.md)に従う。形式判定とは別の規則であり、PDF対応によってツリーから全種類を開けるようにはしない。

## 入力・出力とルール

### 形式とオープン

- 拡張子`.pdf`を大小文字を区別せずPDFと判定する。それ以外は既存のUTF-8 Markdown読み込みとして扱う。`.md`・`.markdown`だけに限定せず、拡張子なし・その他のファイル名を従来どおり扱う。
- 内容による形式推測は追加しない。PDFの解析失敗時にMarkdownとして再試行しない。
- 初期対象はパスワード入力を必要としないPDFとする。パスワード入力UIは追加しない。
- 共通のオープン入口・同一文書確認・非同期要求の順序制御を使う。同じ文書のopenで読み直さない既存動作を維持し、古い要求の完了で新しい表示を上書きしない。
- PDFはバイト列を読み込めただけではオープン成功としない。解析の成否もGUIの完了・エラー処理とCLI応答へ反映する。文書読み込みの完了と、レイアウト後の位置適用・全ページの描画完了は区別する。
- `--line`はMarkdown専用とし、PDFでは同一文書のopenでも成功扱いより前に明示的な未対応エラーを返す。本文の読み込み・解析・位置変更は行わず、ページ番号には読み替えない。PDF URLフラグメントの動作は本仕様から追加しない。

### スクロールとズーム

本文にフォーカスがあるNormalモードで次のキー操作を使う。[スクロール仕様](navigation.md)と同じアプリ側の入力制御を通す。

| キー | PDFでの動作 |
|---|---|
| `j` / `k` | 下／上へ40論理pxスクロール |
| `Ctrl+d` / `Ctrl+u` | 下／上へviewportの半分を移動 |
| `Ctrl+f` / `Ctrl+b` | 下／上へviewport全体を移動 |
| `gg` / `G` | 文書の先頭／末尾へ移動 |

小刻みスクロールはPDFのフォントサイズに依存しない固定の論理表示距離とする。半分／全体の基準は本文viewportであり、PDFページ単位のジャンプではない。すべての移動を先頭・末尾の有効範囲に収める。PDFにMarkdownソース行の概念は適用しない。マウスホイールによるスクロールにも対応する。

初期表示は幅合わせとし、ズームは[PDFズームのLua API](pdf-zoom.md)から操作する。`+`・`-`・`=`・`p`の組み込み割り当てはなく、任意の`plugins/pdf_zoom.lua`を明示ロードした場合だけNormal用に登録する。Search・Command・選択パネルの文字入力を奪わない。既存app keymapには本文フォーカス条件がないため、Normalのツリーで未処理のキーもappへ届く。幅合わせのresize追従、手動ズームでのfit解除、ページfitのtoggle・最上部ページ基準・可視性の制限は同仕様に従う。

### 画面と入力の所有

- キーバインド・モード・入力UIはアプリ側が管理する。PDFビューアー内蔵のショートカット・検索欄・ページ番号入力・ヘッダーは使わない。
- 同じキー操作をアプリとPDF側で二重実行しない。PDF側の移動ショートカットを止めるために、Search・Command等の無関係な文字入力まで一律に無効化しない。
- PDF本文のクリックで本文フォーカスへ接続し、アプリのキー操作を使えるようにする。Search・Command中の文字入力は維持する。
- PDF専用のローカル検索UIは設けない。状態行へのページ情報表示は将来の候補であり、初期要件ではない。

### 初期版の検索・再読み込み・履歴

- PDF表示中は`F5`で再読み込みしない。Markdownの`F5`は変更しない。
- 戻る／進むでPDFへ戻る場合は、常に先頭を幅合わせで表示する。PDFの位置・倍率は復元しない。文書間の履歴自体とMarkdownの位置復元は維持する。同一ファイルのopenは履歴復帰ではなく、位置・倍率を変更しない。
- 本文フォーカスのNormalで`/`を押してもSearchへ移らず、`n` / `N`でも検索を実行しない。既存の下部入力行（INPUT）の通知機構で未対応を知らせ、文書・位置・倍率・履歴を保持する。英語文言の正本は[通知一覧](viewer-ui.md#表示言語と通知)とする。状態行・ダイアログ・トースト・PDF独自欄へは表示せず、独自の通知時間や消去規則は追加しない。
- Search中に外部CLIでPDFへ切り替えた場合は、Searchモードと入力中の文字列を維持し、入力を通知で上書きしない。PDF検索は実行せず、IME未確定中のEnterは既存規則で保護する。変換確定後のEnterでは編集中の検索語Bを確定せず、直前の確定語Aを保持する。編集とpreviewを終了してNormalへ戻り、同じ未対応通知を表示する。その後Markdownへ戻る場合はAで再計算する。Searchを継続したままMarkdownへ戻る場合はBを優先する。
- 確定済み検索語はMarkdownからPDFへ引き継ぐが、Markdownの一致座標・ハイライトをPDFへ適用しない。Markdownへ戻る際に対象本文で再計算し、Search中は確定語より編集中の入力を優先する。既存のコマンド契約は変更しない。

## 例外時の振る舞い

ファイル読み込み失敗・PDF解析失敗はエラーとして通知する。[共通通知方針](viewer-ui.md#表示言語と通知)に従い、表示中の文書・表示位置・履歴を保持する。ツリー起点ではツリーとそのフォーカスも保持する。外部CLIには失敗を返す。Search・Command中の入力モードと文字列はエラーのために置き換えない。PDFのエラーをMarkdownの不正UTF-8として扱わない。

## 後続対応との境界

- 初期範囲にPDFの検索・OCR・フォーム編集を含めない。上流が対応していても、PDF内部リンク・アウトライン・フォームを自動的に初期範囲へ追加しない。
- PDFの自動更新と履歴の位置・倍率復元は初期範囲に含めない。初期版の`F5`非対応と履歴復帰時の先頭・幅合わせは上記に従い、後続版での提供時期は定めない。
- 将来のPDF検索はMarkdownと同じアプリのSearchモードへ統合し、PDF内蔵検索欄には依存しない。検索語設定・次／前の一致移動・強調解除を操作として扱う。
- 将来はファジー検索を目指すが、部分列一致か誤字許容か、順位付けの方式は選定していない。Markdownの現在のリテラル検索を変更する要件ではない。
- テキスト一致をPDF上の矩形へ対応付けられることを保ち、非連続な一致も扱える余地を残す。OCRや縦書き・多段組みの正確なテキスト抽出を保証するものではない。

## 受け入れ条件と性能確認

- 起動／CLI・ツリー・Markdownリンクの各入口からPDFが同じ本文領域へ表示され、Markdownへも切り替えられる。`.PDF`もPDFとなり、拡張子なし・その他の名前は従来のMarkdownとして扱われる。
- 小刻み・半viewport・全viewport・先頭／末尾への移動と拡大・縮小・幅合わせがアプリの操作から実行され、内蔵UIやショートカットによる二重実行がない。
- PDFでは`F5`で再読み込みせず、履歴でPDFへ戻ると先頭・幅合わせとなる。同一ファイルのopenでは位置・倍率を維持し、Markdownの更新・履歴復元は変わらない。
- PDFのNormalで`/`・`n`・`N`は検索せず入力行へ通知する。Search中の外部切り替えは入力を保持し、IME確定後のEnterでNormalへ戻って通知する。Markdownへ戻ると対象本文の一致を再計算し、古い一致座標をPDFへ適用しない。
- 幅合わせは本文幅変更へ追従し、手動ズームで解除する。ズームは中央付近のPDF位置を保ち、移動は有効範囲へ収める。
- 不正PDF・読み込み失敗・PDFへの`--line`を成功にせず、現在の文書・位置・履歴を保持する。交錯する要求で古い結果が表示を上書きしない。
- 代表的な日本語PDF、画像の多いPDF、数百ページのPDFを使い、初回表示までの時間、スクロール中の入力応答と描画待ちを観測する。上下方向の反復スクロール・文書切り替えでメモリが無制限に増え続けないことを確認する。
- 性能確認では対象版、ハードウェア・OS、PDFのページ数・容量・内容特性、操作条件と測定方法・結果を記録する。数値の合格閾値は定めていないため、測定値と観察した問題を根拠に評価する。

これらは将来の実装を確認する条件であり、実測結果やビルド互換性の確認済みを示すものではない。
