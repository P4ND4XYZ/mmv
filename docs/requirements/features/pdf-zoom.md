# PDFズームのLua API

[全体像に戻る](../index.md) / [PDF表示](pdf-viewing.md)

## 目的と基本の流れ

表示中のPDFをLuaから拡大・縮小・fitし、適用済み倍率を参照します。標準キーは追加せず、利用者が任意のキーやUIへ接続します。

1. イベントcallbackから `require("mmv").pdf` の操作関数を呼ぶ。
2. 受理結果をbooleanで受け取る。レイアウト前なら適用を待つ。
3. 必要に応じて `get_zoom()` で適用済み倍率を読む。

## 入力・出力とルール

すべてメソッドではなく関数です。options・owner・on_completeはありません。余分な引数、引数不足、不正な型・値は作用前のLuaエラーです。数値文字列などの暗黙変換は行いません。

| 呼び出し | 動作 |
|---|---|
| `mmv.pdf.set_zoom(factor)` | 有限・正のnumberを受け付け、0.01〜3.0に収めて適用 |
| `mmv.pdf.zoom_in()` | 適用時の現在倍率を1.1倍 |
| `mmv.pdf.zoom_out()` | 適用時の現在倍率を1.1で割る |
| `mmv.pdf.fit_width()` | 幅合わせを有効化。同じ呼出しで解除しない |
| `mmv.pdf.fit_page()` | ネイティブのページfitを切り替えるtoggle |
| `mmv.pdf.get_zoom()` | 適用済み倍率のnumber。PDFでない場合と初回の有効レイアウト前はnil |

変更関数は要求を受理すると `true`、呼出し時点でPDFがなければ `false` です。`true` は適用完了・鮮明なラスタ画像の描画完了を保証しません。適用結果callbackや結果codeは提供しません。初期化中の全APIと、render/render_item中の変更は禁止です。getterは実行時のイベント・render/render_itemで使えます。

変更要求は呼出し時の表示に結び付き、表示置換で未適用の旧要求を黙って破棄します。同じパスを開き直した別表示にも移しません。同一PDFの通常openがno-opなら表示と保留要求を維持します。変更要求は受理順に適用し、相対ズームは前の要求の適用値を基準にします。保留中のgetterは未来の値ではなく直前の適用値を返します。

## 倍率・位置・fitの継続

- 手動ズームは上限・下限で倍率が変わらない場合もfitを解除します。幅fitとページfitは同時に有効になりません。位置保持はネイティブ実装に従い、viewport中央付近の位置を有効スクロール範囲に収めます。
- 幅fitはウィンドウやツリー表示による本文viewportの変更に追従します。
- ページfitは、適用時のviewport最上部のページを基準に幅・高さを合わせます。中央ページの選択、ページ中央への再配置、ページ全体の可視性は保証しません。連続表示のままで、単一ページ表示にはしません。
- ページfit中にスクロールするだけでは倍率は変えません。resize時はその時点の最上部ページを基準に再計算します。対象ページを固定保存しません。再呼出しで解除し、解除時は現在倍率を保持します。
- 手動・fitとも倍率範囲は0.01〜3.0です。極端なページ形状や小さいviewportでは全体が収まらない場合があります。既存の浮動小数点精度・微小差の許容判定を維持し、微小な倍率差の厳密な適用を約束しません。
- API自体は本文フォーカスやNormalモードを要求せず、mode・focusを変更しません。キーの配送条件は既存のkeymap規則に従います。
- 初期表示の幅fit、履歴復帰の先頭＋幅fit、同一PDFの通常openで状態を保持する規則は変更しません。倍率の永続化・新GUIコントロール・ページジャンプAPI・fitモードgetterは追加しません。

## 任意プラグイン

`plugins/pdf_zoom.lua` を利用者のinit.luaから明示ロードして `setup()` を呼び出した場合だけ、Normalで `+`：拡大、`-`：縮小、`=`：幅fit、`p`：ページfit toggleを登録します。未ロード時はこれらのPDFズーム操作を割り当てません。`standard.lua` からの自動ロードや利用者init.luaの生成はしません。ロード後に上書き・解除できます。コピーとdofileの例は[plugins README](../../../plugins/README.md)を参照してください。

## 受け入れ条件

- 型・引数数・phaseの違反を作用前に拒否し、PDFなしのfalseと有効要求のtrueを区別する。
- レイアウト待機、相対操作の順序、適用済みgetter、表示置換による旧要求破棄を確認できる。
- ネイティブのfit切替・resize追従・手動解除を維持し、ページ中央配置や全体可視性を保証しない。
- プラグイン未ロード時の無割当、明示ロード、後からの上書き・解除と入力routing保護を確認できる。
