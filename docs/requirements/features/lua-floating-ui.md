# LuaによるフローティングUI

[全体像に戻る](../index.md)

## 目的と位置づけ

利用者がLuaでアプリ内の一時的なウィンドウを作り、一覧・入力・生ソース・ボタンなどを用途に合わせて組み合わせられるようにします。固定のtext/select APIや、既存の選択パネルのレイアウトだけを公開する機能ではありません。

公開Lua APIの追加と、そのAPIだけを使う同梱Luaによる既存リンク選択の置き換えを対象とします。呼び出し・値・イベント・寿命の契約は[Lua公開API](lua-api.md)を正本とします。本文とツリーの固定paneを任意分割する機能とは区別します。

## 基本の流れ

1. 起動時に同梱Luaが標準のリンク選択キーを登録し、利用者はLua設定でキーを上書き・解除したり、別のUIを登録したりする。
2. 登録したキーなどの操作から、状態を用意し、表示ツリーを返すrenderでフローティングウィンドウを開く。
3. 入力・選択・ボタン操作のイベントで状態や部品を操作する。再描画だけでは入力・IME・選択・フォーカス・スクロール位置を初期化しない。
4. 必要に応じて文書の読み取り専用snapshot、候補、ソース位置、ファジーマッチを使い、既存の遷移処理を呼ぶ。
5. 終了時には部品・購読・未配送イベントを安全に無効化する。Lua callbackの成否によって解放を中断しない。

## 対象範囲

### 対象

- Luaによるアプリのキー登録・解除。
- modal/nonmodalと複数のアプリ内フローティングウィンドウ。
- row、column、text、list、input、source、buttonの合成、状態の保持、部品操作、イベントと寿命管理。
- 現在文書のsnapshot、リンク候補、リンク元のソース位置、実際の本文置換の通知。
- 文字列同士のファジーマッチと、既存のリンク遷移・履歴への接続。
- 非同期遷移の結果、通知、Luaの実行・renderエラーの扱い。

### 対象外

- ファイルツリー自体のLua化。将来の拡張を妨げないよう、公開APIの利用先をbody/treeの固定区分にしない。
- 独自コマンド、設定のホットリロード、フローティングウィンドウ自体のmove。
- GPUI Entityや描画コンテキストの直接公開。
- Luaでのファイル読み込みや履歴の再実装。

## UIとホストの分担

LuaはUI構成・状態・振る舞い、候補の照合対象・並び順・選択・プレビューの接続、遷移の呼び出し、本文置換時のリンクパネル終了を担当します。

Rustは描画・IME・実フォーカス・スクロール、文書解析、照合計算、既存の遷移と履歴、安全なイベント配送と解放を担当します。汎用のフローティングウィンドウは文書の意味を持たず、本文置換だけで自動終了する機能にはしません。古い文書の遷移先検証は、Luaの終了処理とは独立して残します。

GUIのアプリ生成文言は[既存の英語表示規則](viewer-ui.md#表示言語と通知)に従い、本文・入力・名前・パスを翻訳しません。

## 同梱リンク選択

利用者向けの配置・操作・候補・状態保持は[画面と操作モード](viewer-ui.md#共通の選択パネル)と[リンクと履歴](links-history.md#キーボードによるリンク選択)を維持します。

- 標準のNormalモードの`f`も同梱Luaで登録し、利用者が変更・解除できるようにする。Rustにリンク選択専用の`f`を残さない。
- 表示名と宛先を別々に照合し、どちらかが一致する候補を最大スコアの降順で並べる。同点と空入力では本文順を保つ。
- ソースプレビューはリンク先ではなく、取得した文書内でリンクが記述された位置を表示する。解析で得た範囲を使い、ファジーマッチから位置を推測しない。
- 選択候補が変わったときだけリンク位置への一度限りのスクロールを要求する。同じ選択の再描画やサイズ変更で手動閲覧位置へ巻き戻さない。
- 候補なし・位置不明ではLuaが古いsource部品を外し、前候補の表示を残さない。
- 入力に対応する一覧更新前の古い候補、閉じたパネル、現在本文ではなくなったsnapshotの遷移先から誤実行しない。
- 実際の本文採用後の通知を購読してパネルを閉じる。読み込み要求だけ、本文を保持する失敗、古い未採用完了、スクロール、画像・Mermaid完了では閉じない。

### 公開APIでの接続の流れ

1. キーcallbackで`mmv.document.current()`からsnapshotを取得し、`doc:links()`と`doc:source()`を得る。文書がなければリンク選択を開始しない。
2. queryとselection等のstateをrender外で用意し、`ui.float.open`のrenderからrow/column/list/input/sourceを合成する。render内では状態更新や部品操作を行わない。
3. queryから表示名・宛先を別々にfuzzy照合し、一致候補だけを最大score順・同点本文順に並べる。listのreset_onへqueryを渡し、inputのbindとlistのselectionは別stateに接続する。
4. listのrender_itemで一致範囲をtextのhighlightsへ接続する。選択に対応するsource記述へ元sourceとsource_rangeを渡し、候補なし・位置不明では古いsource部品を外す。
5. 選択stateと表示の同期後のon_selection_changedでは、候補と既知の範囲がある場合だけsourceハンドルへscroll_toを一度要求する。同IDでは通知しないため、検索変更や再描画だけで手動位置へ戻さない。
6. inputの追加keysからlistの次/前/confirm、sourceの半画面scrollを明示的に呼ぶ。既定のsubmitは選択listのconfirmへ接続し、IME確定Enterでは実行しない。
7. openが戻った後、同じ呼び出し元Lua処理内でowner付きon_replaced購読を接続する。初回選択通知はその処理終了後なので、windowと購読を設定した上で部品を操作できる。
8. on_confirmではIDからtargetを確保してパネルを閉じ、navigation.openで既存遷移を呼ぶ。終了後も結果が必要ならownerを省略し、callbackで通知するか、on_completeを省略してホスト通知を使う。本文置換は購読からcloseし、エラー処理はon_errorやホストfallbackへ接続する。

この流れは公開契約の接続を説明するもので、同梱Luaの実装済み・実行検証済みを示さない。

## 例外時の振る舞い

不正なAPI呼び出しはLuaエラーとします。eventやrenderの未処理エラーだけで、ホストが一律にウィンドウを閉じることはしません。Lua側は捕捉・通知・再試行・終了を選べます。初回生成失敗で不完全なウィンドウを残さず、後続render失敗では直前の正常表示を保持します。エラー時も古い一覧の確定は禁止します。

設定の実行・検証は部分適用せず、成功後に一括で有効化する契約を維持します。既存の設定失敗時の扱いは[表示・配色設定](display-settings.md#設定に失敗した場合)に従います。

## 受け入れ条件

- [ ] 公開APIだけで既存のリンク選択を再現する同梱Luaを構成でき、標準`f`を利用者が上書き・解除できる。
- [ ] modal/nonmodalと複数枚の重なり・キー・外クリック・フォーカス復帰が公開契約どおりになり、背後の非同期処理は継続する。
- [ ] 再描画で入力・IME・選択・フォーカス・スクロールを保持し、ソースへの移動要求は一度だけ適用される。
- [ ] 候補・確定先・リンク元範囲が対応し、候補なし・位置不明・本文置換後に古いプレビューや誤遷移が残らない。
- [ ] プレビュー操作で本文の閲覧位置・検索・履歴・ツリーを変更しない。
- [ ] 初回renderと初期イベントの順序、部品の失効、未同期一覧の確定禁止、render失敗時の表示保持を確認できる。
- [ ] owner終了後に未実行callbackや購読が残らず、遷移自体の取消とは混同されない。結果は成功・警告付き成功・失敗・未採用に分類され、配送対象が有効な完了callbackへ一度だけ通知される。
- [ ] Luaエラーでアプリが異常終了せず、解放や終了後イベントの無効化がLuaの成否に依存しない。設定は部分適用されない。
- [ ] 自動テストに加え、Windows実機で日本語IMEとフォーカスの振る舞いを確認する。
