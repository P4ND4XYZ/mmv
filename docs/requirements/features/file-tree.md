# ファイルツリー

[全体像に戻る](../index.md)

## 要件

### 表示と対象範囲

- Windows向けの読み取り専用Markdownビューアーで、左をツリー、右を本文とする固定2領域のpaneを使う。任意分割、複数本文、汎用paneプラグインは対象外とする。
- `Ctrl+Shift+e`でツリーの表示／非表示を切り替える。通常幅は240論理pxとし、ドラッグリサイズと幅保存は行わない。本文paneの最小幅は240論理pxとし、ウィンドウの最小幅は本文240＋ツリー240＋境界線などの必要幅を確保する。
- Markdownに限らず全種類のファイルと隠しファイルを表示し、拡張子や隠し属性で絞り込まない。`.gitignore`は参照しない。`.git`は項目として表示するが内部は展開しない。
- 通常フォルダーだけを展開する。シンボリックリンク・ジャンクションはファイル／フォルダーとも表示だけとし、リンク先を開いたり展開したりしない。その他のreparse pointも表示だけとし、展開しない。クラウド固有の特殊フォルダーへの対応は対象外とする。
- フォルダーを優先し、名前の大小文字を区別しない名前順に並べ、同順位は元の名前で固定する。自然順は使わない。
- ツリーは構造の閲覧専用とする。ファイルを開く・プレビューする・外部アプリを起動する操作、作成・編集・削除・移動は対象外とする。行クリックによる選択・展開も不要とする。
- 表示切替、カーソル移動、展開・折り畳み、フォーカス移動では本文を切り替えず、閲覧履歴を追加しない。

文書を開く操作は[ファイル表示と更新](file-viewing.md)に従う。リンク先非展開の制約はツリー内だけに適用し、CLI・文書内リンクによる文書表示を変更しない。

### 初期表示と保持範囲

- ユーザー単位のLua設定の`tree.visible`で起動時の表示状態を指定し、既定値は`false`とする。初期フォーカスは本文とする。
- 設定の読み込み先・反映時期・不正値の扱いは[表示・配色設定](display-settings.md)に従う。文書側のLuaは実行しない。
- ルートを1行で表示する。起動時と別ルートへの切り替え時は、ルート行にカーソルを置き、ルート直下だけを展開する。現在文書まで自動展開・スクロールしない。
- 非表示から再表示した場合と同一ルート内の文書移動では、展開状態・カーソル・ツリースクロールを保持する。別ルートではこれらを初期化する。再起動時の復元は行わない。
- 起動後の可視状態は文書・ルート変更でも保持するが、Luaへ書き戻さず、再起動時は設定値を使う。

### カーソルと描画

- 現在本文に表示中のファイルは強調しない。現在のファイル名は下部の状態行で確認する。
- ツリーカーソルは行全体の背景色で示す。ツリーにフォーカスがある場合は明瞭な背景と左端の細い縦線、本文にフォーカスがある場合は控えめな背景だけとする。文字色を薄くしない。
- フォルダーの展開記号は閉じた状態を`▸`、展開状態を`▾`とする。
- カーソル移動時は、その行が見える最小限だけスクロールする。
- 標準配色を使い、ツリー専用のLua配色APIは追加しない。

### 入力とpane移動

ツリーにフォーカスがあるときは次の操作を使う。

| キー | 動作 |
|---|---|
| `j` / `↓` | 次の行へ |
| `k` / `↑` | 前の行へ |
| `h` / `←` | 展開中のフォルダーを閉じる。それ以外は親へ |
| `l` / `→` | 閉じたフォルダーを展開する。展開済みなら先頭の子へ |
| Enter | フォルダーを開閉する。ファイルでは何もしない |
| `g g` / Home | 最初の行へ |
| `G` / End | 最後の行へ |
| `r` | 一覧を更新する |

pane移動は`Ctrl+W`を押した後の`h`で左のツリーへ、`l`で右の本文へ行う。移動先がない場合や既に移動先にいる場合は何もしない。非表示のツリーをpane移動だけで表示しない。

ツリー入力と本文入力は分離する。ツリーでは本文検索・履歴移動・本文再読み込み（`F5`を含む）を受け付けず、本文を同時にスクロールしない。Search・Command・リンク選択パネル・IME変換中はpane移動とツリー表示切替を受け付けない。`Ctrl+W`の連続入力は既存の`g g`と同じGPUI標準のキー割り当て機構に従い、取消・待機時間・無効キー・修飾キーに独自規則を追加しない。

### 文書に応じたルート

- 採用済み文書の正規化済みパスの親から祖先へ探索し、最も近い`.marksman.toml`または`.git`があるフォルダーをルートにする。なければ文書の親を使う。
- 判定マーカーは`tree.root_markers`で設定する。既定値の置換、空配列、名前・配列の検証は[表示・配色設定](display-settings.md#ルート判定マーカー)に従う。
- CLI・文書内リンク・履歴移動による文書変更の成功時にルートを追従させる。読み込み失敗では現在の本文とツリーを変更しない。
- ルート探索中は旧ツリーを操作できない状態にするが、取得中の文言は出さない。同一ルートなら保持した状態で再開し、一覧を再取得しない。別ルートなら初期化して新ルート直下を取得する。
- 非表示中に文書が変わった場合は再表示時にルートを確認し、別ルートなら新ルートを初回取得する。再表示したという理由だけでは一覧を再取得しない。
- ツリールートは表示範囲であり、本文のリンク・画像の相対パス基準や、ルート外文書への移動を制限するものではない。

### 取得と更新

- フォルダー展開時と明示的な更新操作時だけ一覧を更新する。ツリーの自動監視は行わない。
- 展開時は対象フォルダーの直下を一括取得する。未展開の内部を再帰取得せず、部分取得・続きを取得する機能や大量項目向けの特別対応は求めない。再展開時は再取得する。
- `r`はルート直下と展開中フォルダーの直下を再取得する。閉じたフォルダーの内部は取得しない。マーカーの再探索や本文の再読み込みは行わない。
- 一覧I/Oの完了待ちで本文や他の利用可能な箇所の操作を止めない。取得中の表示は不要とする。初回は子を表示せず、再取得中は既存一覧を残す。
- 同じフォルダーへの重複取得はまとめる。ルート変更・折り畳み・親削除などで不要になった結果は採用しない。
- 非表示化だけでは取得を無効化しない。同じルートに対する有効な結果は非表示中も状態へ保存し、再表示時に利用する。初回取得中に再表示した場合も新しい取得を重ねず、その完了を待つ。非表示中の文書変更に伴うルート確認は前節に従い、別ルートと判明した場合は旧ルートの状態・結果を使わない。

### 更新後のカーソル

更新後もカーソル項目が存在すればその項目を維持する。ファイル／フォルダーのどちらでも、削除された場合は更新前の並びを基準に次の順で移す。

1. 後ろにある残存兄弟の最初。
2. 前にある最も近い残存兄弟。
3. 親。
4. 存在する最も近い祖先。

同じ行番号を維持して別項目を選ぶ方式にはしない。

### アクセスできない場合

- 取得失敗は項目の削除や空フォルダーと区別し、既存一覧・カーソルを保持して更新失敗を表示する。`r`、または閉じた後の再展開で再試行できる。
- ルートが利用不能な場合はルート行を残し、そこへカーソルを移す。文言は「アクセスできません。」だけとし、再試行案内は表示しない。ルート名・パス・フォーカスを保持し、`r`とpane移動は使える。
- ツリーエラーで本文やSearch・Commandの入力欄を置き換えない。他の利用可能な枝と本文は引き続き利用できる。
- マーカー探索自体がアクセス拒否になった場合は文書の親を暫定ルートとする。探索失敗や暫定ルートであることは画面へ通知しない。親の一覧取得も失敗した場合は、ルート利用不能時の表示を適用する。

## 受け入れ条件

以下は実施結果ではない。

- [ ] `tree.visible`のtrue／false／省略で初期表示が決まり、初期フォーカスは本文となる。
- [ ] ウィンドウ最小幅で本文paneの240論理pxとツリーの240論理px、境界線などの必要幅が確保される。
- [ ] 全ファイル・隠しファイルが指定順で表示され、`.git`内部、symlink・junctionを含むreparse pointは展開されない。
- [ ] 表示切替・同一ルート文書移動で展開・カーソル・スクロールが保持され、別ルートではルート行カーソルと直下展開になる。
- [ ] ツリーの各キーとpane移動が動作し、本文検索・履歴・F5へ入力が漏れない。入力中・パネル表示中・IME変換中はpane移動・表示切替を受け付けない。
- [ ] ツリー操作でファイルが開かれず、本文・履歴・入力が再初期化されない。
- [ ] 文書変更時のルート追従、探索中の操作禁止、読み込み失敗時の状態保持を確認できる。
- [ ] 再表示だけでは再取得せず、`r`は表示中の展開範囲だけ更新し、マーカー再探索と本文再読み込みをしない。
- [ ] 初回取得中に隠しても有効な結果は保存され、再表示では保存済み一覧または進行中の取得を利用し、重複取得しない。
- [ ] 遅延・重複・折り畳み・ルート変更・親削除後の不要な結果で古い一覧やカーソルが復活しない。
- [ ] マーカー探索のアクセス拒否では画面通知なしで文書親を使い、その親の一覧取得失敗とは区別する。
- [ ] 削除時は残存兄弟・親・祖先の規則に従い、取得失敗時は削除と区別して既存一覧とカーソルを保持する。
- [ ] ルート利用不能時もルート行・フォーカス・`r`・pane移動と本文を維持し、指定文言だけを表示する。
