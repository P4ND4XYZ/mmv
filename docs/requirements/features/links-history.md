# リンクと履歴

[全体像に戻る](../index.md)

## 目的と位置づけ

関連文書や見出しへのリンクをたどり、履歴を使って移動前後の閲覧位置を行き来できるようにします。

## 要件

### リンク

リンクはマウスクリック、またはNormalモードの`f`で開くリンク選択パネルから開く。Vimium風に本文上へ文字ラベルを重ねる方式は対象外とする。

| リンク先 | 動作 |
|---|---|
| 同じファイル内の見出し | 指定された見出しへ移動 |
| 別のローカルMarkdown | このビューアーで開き、現在の表示を置き換える |
| 別のローカルMarkdown内の見出し | ファイルを開き、指定された見出しへ移動 |
| Webページ | 既定のブラウザーで開く |

- 相対パスは表示中の文書を基準に解決する。絶対パス、`file://`、空白などのURLエンコードに対応する。
- リンク先ファイルを読み込めない場合は、現在の文書を保持してエラーを表示する。
- ファイルは開けても指定の見出しがない場合は、そのファイルの先頭を表示して通知する。同一ファイル内でも、指定の見出しがなければ先頭を表示して通知する。

### キーボードによるリンク選択

#### 基本の流れ

1. Normalモードで`f`を押し、リンク選択パネルを開く。検索欄は毎回空にし、候補があれば先頭を選択する。
2. 表示名やリンク先の一部を入力して候補を絞り込み、キーボードで選択する。パネル共通の操作とIMEの扱いは[共通の選択パネル](viewer-ui.md#共通の選択パネル)に従う。
3. Enterで選択したリンクを確定する。候補が1件でも自動では開かない。候補がなければEnterは何もしない。
4. 確定時にパネルを閉じ、クリックと同じ動作でリンクを開く。ローカルMarkdownや見出しへの移動、履歴、読み込み失敗時の文書保持も共通とする。

#### 候補の範囲と表示

- 表示中の文書全体に含まれるリンクを対象とする。画面内に見えているリンクだけには限定しない。
- ローカルMarkdown、同一文書内の見出し、別のローカルMarkdown内の見出し、Webページへのリンクを含める。画像の埋め込み自体は候補に含めない。
- リンクの表示名、リンク先のパスまたはURL・見出し、リンクの種類を表示する。同じ表示名のリンクもリンク先で区別できるようにする。
- 表示名と解決後のリンク先がともに同じ候補だけをまとめ、最初の出現位置を本文順の基準とする。見出しが異なるリンク先や、表示名が異なるリンクは別候補とする。

#### 絞り込みと順序

- 表示名とリンク先をファジーマッチの対象とし、入力した文字が連続していなくても順に一致する候補を探せるようにする。たとえば`dsg`で`design`を探せる。
- 英字の大文字・小文字は区別しない。日本語は入力した文字で照合し、ローマ字の読みから日本語を探す機能は対象外とする。
- 空入力では本文での出現順とする。入力がある場合は一致度のスコア順とし、同点なら本文順を維持する。
- 表示名とリンク先の一致箇所を強調する。
- 入力が変わるたびに候補を更新し、先頭候補を選択する。
- 候補がない場合は「一致するリンクがありません」と表示する。
- fzf固有の検索構文は初回の対象外とする。外部のfzfコマンドのインストールや起動は必要としない。
- パネルの検索入力は本文検索とは独立させ、確定済みの本文検索語を変更しない。

#### 取消・文書更新・失敗

- 取消ではリンクを開かず、取消自体によって本文のスクロール位置や履歴を変更しない。
- 自動更新や外部CLI操作などで本文が置き換わった場合は、パネルを閉じてその旨を通知する。閉じたパネルの候補から古いリンクを開かない。
- 本文の読み込み要求を受けただけ、または読み込みに失敗して本文が保持された場合は、本文置換として扱わない。
- 画像やMermaid図の描画完了、外部CLIによるスクロール・先頭／末尾への移動だけではパネルを閉じない。外部操作による表示位置の変更はそのまま受け付ける。
- 確定後のリンク先の読み込みに失敗してもパネルは再表示せず、元の文書・閲覧位置・履歴を保持し、Normalモードの入力行にエラーを表示する。

### 見出しリンクのID

見出しから自動生成するIDは、[GitHubのSection linksの規則](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#section-links)に合わせる。この互換方針は見出しIDを対象とし、GitHubの全機能や画面の再現を意味しない。

- 英字を小文字にし、空白をハイフンへ変換する。見出しの装飾記法はIDに含めない。
- 日本語の見出しにも対応する。
- 同じ文書内で生成したIDが衝突する場合は、`-1`、`-2`などの番号を付けて一意にする。見出しの階層ごとではなく、文書全体で判定する。
- たとえば`## Getting Started`は`#getting-started`、最初の`## 使い方`は`#使い方`、2つ目の`## 使い方`は`#使い方-1`で参照する。

### 履歴

- ファイル間の移動と、同じファイル内の見出しリンクによる移動を対象とする。
- 通常のスクロールは履歴に含めない。
- `Ctrl+o`で戻り、`Ctrl+i`で進む。
- 戻る／進むときは、その履歴の閲覧位置を復元する。再読み込みやMermaid図の追加時に内容を基準に位置を保つ処理とは区別し、履歴での位置復元は対象に含める。
- 履歴先の文書が変更されていても、保存していた上端からのスクロール距離を復元する。文書が短くなった場合は、スクロール可能な末尾までに収める。
- 履歴先の文書の読み込みに失敗した場合は、現在の文書と履歴上の位置を維持する。
- 履歴はアプリ終了まで保持し、次回起動へは引き継がない。
- 戻った後に新しいリンクへ移動した場合は、「進む」側の履歴を破棄する。

## 受け入れ条件

- [ ] マウスクリックとリンク選択パネルのどちらからも、ローカルMarkdownと見出しへのリンクを開き、Webページは既定のブラウザーで開く。
- [ ] `f`で画面外を含む文書全体の候補を表示し、種類・表示名・リンク先を区別できる。重複は表示名と見出しを含む解決後のリンク先が同じ場合だけまとまる。
- [ ] `dsg`による`design`の絞り込み、英字の大小文字を区別しない照合、日本語入力、一致箇所の強調ができ、スコア同点・空入力では本文順になる。
- [ ] 入力変更で先頭候補が選択され、1件だけでもEnterまでは開かない。候補なしでは通知を表示し、Enterで何も開かない。
- [ ] 並べ替え後も選択した候補と実際に開くリンクが一致し、取消では本文の位置・履歴・確定済み本文検索語を変更しない。
- [ ] 本文置換でパネルが閉じて通知され、古い候補を開かない。本文を保持する読み込み失敗、図・画像の描画完了、外部スクロールではパネルを維持する。
- [ ] 読み込み失敗では元の文書を保持し、見出しだけが見つからない場合は開いたファイルの先頭を表示して通知する。
- [ ] 戻る／進むで閲覧位置を復元し、戻った後の新しいリンク移動では進む側の履歴が破棄される。
- [ ] 日本語や同名の見出しを、GitHubの規則によるIDで参照できる。
- [ ] 履歴先の文書が短くなっていれば復元位置を末尾までに収め、読み込み失敗では現在の文書と履歴上の位置を維持する。
