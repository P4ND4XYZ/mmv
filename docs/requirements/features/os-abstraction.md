# OS抽象化と共通契約

[全体像に戻る](../index.md)

## 目的と位置づけ

WindowsとLinuxのOS差を、パス解決・安全なファイル作成・プロセス起動などの境界へ分離する。文書操作、CLIの意味、設定の有効化、単一起動の判断は共通契約とし、OSごとに異なる製品動作へ分岐させない。

この文書はLinux対応のロードマップや全面的な動作保証ではない。通信・起動・パス・安全性の実現方法と詳細な対象外は[ローカル通信・起動制御](../../design/components/local-control.md)で扱う。

## 対象範囲

- CLIとGUIの設定読込、外部操作、ユーザー単位の単一起動に共通契約を設ける。
- OS固有の配置、ネイティブパス表現、ロック保存先の保護、非アクティブな子プロセス起動を分離する。
- 文書読み込み・履歴・検索・入力モード・GUI配送の既存の責務分担を維持する。
- この抽象化に直接関係しない機能の変更や移植作業を含めない。

## 共通の利用の流れ

1. CLI・GUIは、通信・生存判定・待受開始より前に同じ初期化規則で設定を読む。
2. CLIは既存GUIへ接続する。接続失敗だけではGUI未起動と判断しない。
3. GUIが生存中なら期限付きで接続を待つ。未起動時の自動起動は`Open`だけに限定する。
4. 起動を調停した後にも接続と生存を再確認し、必要な場合だけGUIを起動する。
5. 要求を一度だけ送信し、その要求に対応する結果をCLIへ返す。

## 共通契約とOS差の境界

| 項目 | 共通契約 | OS境界で扱う差 |
|---|---|---|
| 文書操作 | `Open`・Scroll・Top・Bottom・Back・Forwardの意味、終了コード、成功条件を維持する | CLI側で絶対化したネイティブパスの表現 |
| 通信 | 両OSで同じ通信契約と版検証を使う | WindowsのUTF-16コード単位とLinuxの非UTF-8を含むバイト列を不可逆変換せず扱う |
| 単一起動 | セッション・通信先に依存せず、同一ユーザーにつきGUIは1つとする | ユーザーの基準ディレクトリ、所有者・アクセス権・リンクの検査、子へのハンドル継承防止 |
| 生存 | ロックファイルの存在を生存の根拠にしない。競合とI/O・権限エラーを区別する | OSのファイル保護機構 |
| 設定 | 成功時だけ設定・Lua登録を一括で有効化する。読込・実行・検証失敗時は全体を標準へ戻す | 設定の保存先 |
| GUI状態 | 外部操作でフォーカス・入力モード・入力文字列を変えない。CLIの設定評価で既存GUIへ再適用しない | 非アクティブ起動のOS機構と実機確認 |

通信設定の公開APIは[通信設定](display-settings.md#通信設定)、操作・期限・再送禁止は[外部操作](external-control.md)を正本とする。GUI設定を変更するにはGUIの再起動が必要である。生存中GUIへ接続できない場合は失敗し、別GUIを起動しない。

TCPの具体仕様と信頼境界は[通信・フレーム契約](../../design/components/local-control.md#通信フレーム契約)を参照する。

## 配置と安全性の分離

具体的なOS別配置、基準ディレクトリの解決、権限・リンク対策、共有homeの制約は[配置と安全なファイル操作](../../design/components/local-control.md#配置と安全なファイル操作)で定める。呼出側はOS別の固定文字列や権限操作を直接組み立てず、解決済みのパスと明示的なエラーを扱う。設定エラーからの復帰と、安全性を確保できない実行時エラーを区別する。

## 受け入れ条件

- 両OSで同じ外部操作・設定有効化・単一起動の契約を使用し、OS分岐を境界へ限定できる。
- ネイティブパスを置換文字へ変換せずGUIへ渡し、非対応表現は明示的に拒否する。
- GUIの生存中に接続不能でも追加GUIを起動せず、期限内に成功または失敗が返る。
- ロックの残存・異常終了・I/Oエラーを区別し、設定エラー時にも設定・登録の一部だけが残らない。
- 境界の自動検証と実GUIの確認を区別し、未確認のOS・環境の動作保証としない。
